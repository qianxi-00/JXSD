HTML 常用标签全演示

本文件把课案「常用标签」一节里出现的 8 类标签全部真实跑了一遍。 每块演示都配了「用法 / 为什么这样写」的说明，可以直接右键「查看源代码」对照学习。

<h1>~<h6>标题

作用：表示标题，级别从 h1 到 h6 依次变小、重要性依次降低。 为什么这样写：标题不只是「把字变大」，它带有语义——搜索引擎和屏幕阅读器 靠它理解页面结构。所以不要为了「字大」而用 h1，字号应该交给 CSS 去管。

<p><span>段落与行内文本

<p>：段落，是块级元素——独占一行，前后会自动留白。
<span>：行内元素——不换行、不占整行，专门用来「包裹一小段文字」， 以便只给这一小段单独上样式。它本身没有任何默认外观，是个纯粹的「钩子」。

这是一个段落，用于展示大段文字内容。

这是红色行内文本， 这是大号行内文本， 蓝色大号文本。 
<p>这是一个段落，用于展示大段文字内容。</p>
<span style="color:red;">这是红色行内文本</span>，
<span style="font-size:20px;">这是大号行内文本</span>，
<span style="color:blue;font-size:24px;">蓝色大号文本</span>。
块级 vs 行内，一句话记住：块级元素（div / p / h1 / ul / table） 像「一整块砖」，自己占满一行；行内元素（span / a / img / b / i） 像「一行字里的一段」，和文字排在同一行。

<br>换行（自闭合标签）

<br> 表示「强制换行」，它没有内容，所以写成单个标签即可（这叫空元素 / 自闭合标签）。 注意：不要用连续多个 <br> 来做段间距，那是 CSS 里 margin 的活。

<a>链接

作用：点击后跳转。href（hypertext reference）就是「跳到哪里去」。

  • 跳转到外部网站（课案示例）： 点击跳转到百度
  • 跳转到本文件内的某个位置（锚点）： 回到本文档顶部的「标题」演示
  • 打开新标签页（推荐给外链）： 在新标签页打开 Python 官网
  • 发送邮件：发邮件给 someone@example.com

<img>图片

作用：嵌入一张图片。它也是「空元素」，没有结束标签。
src：图片路径（相对路径 / 绝对路径 / URL 都可以）。 alt：图片加载失败时显示的替代文字，同时也是屏幕阅读器念给视障用户听的内容， 所以 alt 不能省。 width：宽度（只写宽度，高度会自动等比缩放，避免图片被拉变形）。 

<img src="img/demo.png" alt="占位图片" width="200">

<ul><li>列表

<ul> = unordered list（无序列表，前面是小圆点）； <ol> = ordered list（有序列表，前面是 1. 2. 3.）； <li> = list item（列表项）。<li> 必须写在 <ul> 或 <ol> 里面， 不能单独出现。

<table>表格

<table> 表格； <tr> = table row，一行； <td> = table data，一个普通单元格； <th> = table header，表头单元格（默认加粗居中）。 border="1" 是课案里用来显示边框的写法，现代写法应该交给 CSS（见本文件样式里的 table 规则）。

<div>区块容器

作用：<div> 是 division（区块）的缩写，是块级的「万能盒子」， 本身没有任何默认外观，专门用来划分结构、把一组内容打包， 方便后面用 CSS 统一排版（比如「这几个东西排成三列」）。 为什么这样写：网页布局的本质就是「盒子套盒子」，<div> 就是那个盒子。

<header><nav> <main><footer>语义化标签（补充）

这些标签的功能和 <div> 几乎一样（都是块级盒子），但名字自带含义。 为什么用它们：做 SEO（搜索引擎优化）和「无障碍访问」（读屏软件）时， 浏览器和爬虫能直接读懂「这块是导航」「这块是正文」。

<header> 页头
<nav> 导航区： 首页 | 关于 | 联系
<main> 主体内容

页面最重要的正文放在这里，一个页面通常只有一个 <main>。

<footer> 页脚 —— 版权信息、备案号等

补充：想在页面上显示 < 和 > 怎么办？

尖括号在 HTML 里是「标签的开始/结束」，所以想把它当普通文字显示，必须用 实体字符（entity）：
&lt; 显示成 <    &gt; 显示成 >    &amp; 显示成 &    &nbsp; 显示成一个不换行的空格   （← 这里就是用 &nbsp; 挤出来的间距）

本文件里所有展示「代码原文」的 <pre> 块，内部都做了这种转义处理， 所以你才能看到完整的标签写法而不是被浏览器当成标签渲染掉。
