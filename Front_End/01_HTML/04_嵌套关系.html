理解网页结构：嵌套关系与 DOM 树

HTML 文档不是「一长串平铺的标签」，而是一棵树。每个标签是一个节点， 标签里再放标签就形成了父子关系。浏览器把这份文档读取到内存里， 就得到了所谓的 DOM 树（Document Object Model，文档对象模型）。 你后面学的 CSS 选择器和 JavaScript 操作元素，全都是在这棵树上做文章。

一、课案的嵌套示例，真实跑一遍

文章标题

第一段关键词内容

<div class="article">
    <h1>文章标题</h1>
    <div class="content">
        <p>第一段<span class="highlight">关键词</span>内容</p>
    </div>
</div>

页面上那个紫色虚线框就是 div.article， 蓝色虚线框是 div.content， 黄色小块是 span.highlight。 一层套一层的边框，正是嵌套关系最直观的视觉证明。

二、课案的树形图

课案用缩进加 `├──` 的方式画出了这棵树的形状：

div.article
├── h1
└── div.content
    └── p
        └── span.highlight

把它读成一句人话就是：

  • div.article 是根（这一小段结构的根）。
  • 它有两个直接子节点：h1 和 div.content。
  • h1 和 div.content 互为兄弟节点（同一个父亲）。
  • p 是 div.content 的子节点，是 div.article 的孙子（后代）。
  • span.highlight 是最深的一层，只有它自己是「叶子节点」。

三、术语对照表（务必记住，CSS / JS 天天用）

术语含义在本例中
父节点 parent 直接包住我的那一层 p 的父节点是 div.content
子节点 child 我直接包住的那些 div.article 的子节点是 h1 和 div.content
兄弟节点 sibling 和我同一个父亲的其他节点 h1 和 div.content 是兄弟
祖先 ancestor 父、祖父、曾祖父……所有上层 span 的祖先是 p、div.content、div.article、body、html
后代 descendant 子、孙、曾孙……所有下层 div.article 的后代包含上面所有 4 个标签
根节点 root 最顶层，也就是 <html> 整份文档的根永远是 html
为什么这些词很重要？ CSS 里 .article p（后代选择器）和 .article > p（子选择器） 的区别，JS 里 parentNode / children 的用法， 全部建立在这套父子关系上。分不清父子，就写不对选择器。

四、缩进：不影响渲染，但影响你的队友

浏览器解析 HTML 时会把标签之间的换行和空格压缩成一个空格， 所以下面两段代码渲染效果完全一样：

推荐（有缩进，一眼看出层级） 
<div class="article">
    <h1>文章标题</h1>
</div>
不推荐（虽然浏览器能跑） 
<div class="article"><h1>文章标题</h1></div>

结论是：缩进是给人看的，不是给浏览器看的。但嵌套一深， 没有缩进的代码几乎无法维护，所以从一开始就养成"每进一层缩进 2 或 4 个空格"的习惯。

五、嵌套的禁忌：不是随便什么都能塞进去

HTML 对「谁能当谁的父节点」有规则，违反规则时浏览器会自动改写你的结构：

❌ 错误写法：把块级元素 <div> 塞进段落 <p> 里 
<p>一段文字
    <div>我是块级元素</div>   <!-- 非法！ -->
</p>

浏览器遇到这种情况会「贴心」地帮你把 <p> 提前闭合， 变成「p、div、空p」三个兄弟节点 —— 你的层级结构和 CSS 选择器可能因此全部失效， 而页面上不会有任何报错提示。这是新手最容易踩的坑之一。

✓ 正确写法：要放块级元素，就把外层换成 <div> 
<div>一段文字
    <div>我是块级元素</div>
</div>

速记规则：

  • 块级元素（div / p / h1~h6 / ul / table / section）可以包容行元素，也可以包块级元素（<p> 除外，它只能包行内元素）。
  • 行内元素（span / a / b / i）原则上不能包块级元素。
  • <ul>/<ol> 的直接子元素只能是 <li>。
  • <table> 里要有 <tr>，<tr> 里要有 <td>/<th>。

七、开发者工具怎么用（课案：右击查看源代码 / 右击检查）

  1. 右击 → 查看网页源代码（Ctrl + U）
    看到的是服务器发过来的原始 HTML 文本，也就是你写的那个文件本身。 它不会显示 JavaScript 后来动态插入的内容。
  2. 右击 → 检查（Inspect，或直接按 F12）
    打开开发者工具，默认停在 Elements 面板。这里显示的是当前真实的 DOM 树—— 已经被浏览器纠错过、也已经包含 JS 动态修改过的内容。它和「查看源代码」看到的不一样， 这一点极其重要。
  3. 在 Elements 面板里做什么：
    • 把鼠标移到某个标签上 → 页面上对应区域会被高亮，这是找元素最快的办法。
    • 点开右侧的 Styles 子面板 → 看到这个元素最终生效的所有 CSS 规则， 被划掉的表示被更高优先级覆盖了（调试样式必看）。
    • 双击标签名/属性值可以直接改，页面会立刻变化（刷新后还原，不用担心改坏）。
    • 切到 Console 面板可以执行 JS，例如输入 document.querySelectorAll("section").length 回车， 立刻得到本页 section 的数量。
动手练习：按 F12 → 在 Console 里依次运行下面三行，观察输出和页面变化： 
document.querySelector(".highlight").textContent
document.querySelector(".highlight").style.background = "red"
document.querySelectorAll("section").length
