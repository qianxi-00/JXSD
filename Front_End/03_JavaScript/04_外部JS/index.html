外部 JS 文件示例

本页面的所有交互逻辑都来自 js/app.js——一个独立的外部脚本文件。

一、课案原文写法

HTML 文件：

<!DOCTYPE html>
<html>
<head>
    <meta charset="UTF-8">
    <title>外部JS示例</title>
</head>
<body>
<h1 id="title">点击次数：0</h1>
<button id="btn">点我</button>
<script src="app.js"></script>
</body>
</html>

app.js 文件：

let count = 0;
let btn = document.getElementById("btn");
let title = document.getElementById("title");

btn.onclick = function() {
    count++;
    title.textContent = "点击次数：" + count;
};
注意课案把 <script src="app.js"> 放在了 </body> 前面，这不是随便放的： 此时上面的 <h1> 和 <button> 已经被解析出来了， getElementById 才能拿到元素。
本项目把它改进成放在 <head> 里并加 defer， 效果一样但下载不阻塞渲染 —— 这是现代项目的推荐写法。

三、app.js 还做了什么

打开 js/app.js 可以看到完整的、带详细中文注释的代码。 除了课案的计数器，它还演示了下面这些真实项目里天天用的模式：

  1. 在 DOMContentLoaded / defer 之后初始化—— 保证元素一定存在。
  2. 封装到函数里，避免全局变量污染—— 所有代码包在一个 init() 里，只暴露一个入口。
  3. 事件委托——把监听器绑在父容器上，动态新增的项也能响应。
  4. 表单校验 + preventDefault——不让页面刷新。
  5. 状态与视图同步——数据（数组）变了就重新渲染列表， 这是 React/Vue 的核心思想，用原生 JS 也能体会一遍。

    四、外部 JS 为什么是「推荐」做法

    对比项内联 <script>外部 .js 文件
    作用范围单个页面所有引用它的页面
    能否复用❌ 要复制粘贴✅ 一处修改，处处生效
    浏览器缓存❌ 每次随 HTML 重传✅ 会被缓存
    可调试性⚠️ 在 F12 里显示为 index.html:行号✅ 显示为 app.js:行号，能直接打断点
    HTML 可读性❌ 结构里混满逻辑✅ 只剩结构
    适合场景极少量的一次性代码真实项目标准做法
    关注点分离原则： index.html（结构）+ css/style.css（样式）+ js/app.js（行为）。 三个文件各司其职，这也是后面 React/Vue 项目的组织方式原型。

    五、路径与常见错误排查

    现象原因解决
    F12 Console 报 Unexpected token '<' 路径写错了，服务器返回了 404 的 HTML 页面被当成 JS 解析 检查 src 路径
    F12 Network 里 app.js 是红色 404 文件不存在或路径大小写不符 确认文件与 src 字面完全一致
    Cannot read properties of null <script> 在元素之前执行了 移到 </body> 前，或加 defer
    改了 JS 刷新没变化 浏览器用了缓存的旧 JS Ctrl + F5 强制刷新，或 F12 → Network 勾选 Disable cache
    开发时的一个好习惯：F12 → Network 面板勾上 Disable cache， 并保持 DevTools 打开状态 —— 这样每次刷新都拿最新的 JS/CSS，不用按 Ctrl+F5。
