JavaScript 事件处理

事件（Event）就是"用户在页面上做了什么"。JS 通过 事件监听器（listener） 在事件发生时执行一段代码。没有事件，网页就只是一个静态的文档。

<button id="btn1">按钮1</button>

    let btn1 = document.getElementById("btn1");
    let btn2 = document.getElementById("btn2");

    // 点击事件

        alert("按钮1被点击了");
    };

    // 监听方式（更推荐）
    btn2.addEventListener("click", function() {
        alert("按钮2被点击触发");
    });

    // 页面加载完成
    window.onload = function() {
        alert("页面加载完成");
    };
</script>

二、两种绑定方式：onclick 与 addEventListener

// 方式一：onclick 属性（DOM 0 级，老写法）
btn.onclick = function () { console.log("第一次绑定"); };
btn.onclick = function () { console.log("第二次绑定"); };
// ⚠️ 结果：只有"第二次绑定"会执行！后面的把前面的【覆盖】了。

// 方式二：addEventListener（DOM 2 级，推荐）
btn.addEventListener("click", function () { console.log("监听器 A"); });
btn.addEventListener("click", function () { console.log("监听器 B"); });
// ✅ 结果：A 和 B 都会执行，按注册顺序依次触发，互不覆盖。

// 移除监听器：必须传入【同一个函数引用】，所以不能写匿名函数
function handler() { console.log("被移除了"); }
btn.addEventListener("click", handler);
btn.removeEventListener("click", handler);   // ✅ 有效
// btn.removeEventListener("click", function () {});  // ❌ 无效！这是另一个函数对象
对比项onclickaddEventListener
能否绑多个❌ 后绑的覆盖先绑的✅ 可以绑任意多个
能否移除btn.onclick = nullremoveEventListener（需同一函数引用）
选项参数无✅ once / passive / capture
事件类型只能绑"on+事件名"的那一种✅ 任意事件名，含自定义事件
结论一律用 addEventListener

三个常用选项

// once: true —— 只触发一次，之后自动移除（做"只能点一次"的按钮很方便）
btn.addEventListener("click", handler, { once: true });

// passive: true —— 承诺"我不会调用 preventDefault"，浏览器可以立刻滚动，性能更好
// （做无限滚动、滚动监听时必加，否则手机端会卡）
window.addEventListener("scroll", onScroll, { passive: true });

// capture: true —— 在【捕获阶段】触发，而不是默认的冒泡阶段（见下面第四节）
outer.addEventListener("click", handler, { capture: true });

三、事件对象 event

监听器函数的第一个参数就是事件对象，它携带了这次事件的所有信息。

btn.addEventListener("click", function (event) {
    event.type;            // "click"          事件类型
    event.target;          // 真正被点击的那个元素（可能是子元素）
    event.currentTarget;   // 绑定监听器的那个元素（等价于 this，除非用箭头函数）
    event.clientX / clientY;  // 鼠标相对视口的坐标
    event.pageX / pageY;      // 鼠标相对文档的坐标
    event.key;             // 键盘事件：按下的键名，如 "Enter" / "a" / "ArrowUp"
    event.code;            // 键盘事件：物理按键位置，如 "KeyA" / "Enter"
    event.ctrlKey / shiftKey / altKey / metaKey;  // 是否按住了修饰键
    event.timeStamp;       // 事件发生的时间戳

    event.preventDefault();    // 阻止元素的【默认行为】（跳转、提交表单等）
    event.stopPropagation();   // 阻止事件继续【冒泡】到父元素
});

四、事件流：捕获 → 目标 → 冒泡

点击一个元素时，事件其实经历了三个阶段：

  1. 捕获阶段：从 window 一路向下传到目标元素的父级。
  2. 目标阶段：事件到达被点击的那个元素本身。
  3. 冒泡阶段：从目标元素一路向上传回 window。

addEventListener 默认在冒泡阶段触发， 所以点击内层元素时，外层元素的监听器也会被触发。 这就是为什么事件委托能成立。

五、事件委托（Event Delegation）—— 最实用的技巧

问题：列表里有 100 个条目，每个都要绑定删除按钮。如果逐个绑， 就是 100 个监听器；而且之后动态新增的条目没有监听器，点了没反应。

解法：把监听器只绑在父元素上。利用冒泡，子元素的事件会传到父元素， 再通过 event.target 判断"到底是哪个子元素被点了"。 这样动态新增的元素也自动生效。 

// ❌ 传统做法：每个 li 都绑一个（新增的 li 没绑定）
document.querySelectorAll(".list li").forEach(function (li) {
    li.querySelector(".del").addEventListener("click", removeItem);
});

// ✅ 事件委托：只绑一次，绑在父容器上
document.querySelector(".list").addEventListener("click", function (event) {
    // closest 从 event.target 开始向上找最近的匹配元素
    const delBtn = event.target.closest(".del");
    if (!delBtn) return;                 // 点的不是删除按钮，直接忽略
    const li = delBtn.closest("li");     // 找到这个按钮所在的 li
    li.remove();
});

  • 项目 B data-id="2"

验证一下：先点【动态新增一项】，再点新那一项的【删除】—— 它没有任何单独的监听器，但因为委托在父级 <ul> 上，依然能正常工作。 这就是事件委托的威力。

3）表单事件：实时校验 + 阻止默认提交

const form = document.getElementById("my-form");

// input 事件：每输入一个字符就触发 → 做实时校验
nameInput.addEventListener("input", function (event) {
    // event.target.value 就是当前输入框里的内容
    if (event.target.value.length < 2) {
        showError("名字至少 2 个字");
    } else {
        clearError();
    }
});

// submit 事件：点提交按钮或按回车时触发
form.addEventListener("submit", function (event) {
    event.preventDefault();     // ⚠️ 必须！否则浏览器会刷新整个页面
    // ...在这里做校验、发请求...
    console.log("校验通过，这里可以 fetch 提交到后端");
});

七、页面加载事件：window.onload 与 DOMContentLoaded

// 课案原文
window.onload = function () {
    alert("页面加载完成");
};

// 更精确的做法：DOM 一解析完就执行（不等图片）
document.addEventListener("DOMContentLoaded", function () {
    console.log("DOM 准备好了，可以安全地操作元素了");

八、重点回顾 & 常见坑

  • 事件 = 用户动作；监听器 = 事件发生时执行的函数。
  • 一律用 addEventListener，不用 onclick（会被覆盖、无法绑多个）。
  • removeEventListener 必须传入同一个函数引用，匿名函数无法移除。
  • event.target = 谁被点了；event.currentTarget = 谁在听。
  • 事件默认冒泡（子 → 父），用 stopPropagation() 可以打断。
  • 事件委托：把监听器绑在父元素上，用 closest() 定位子元素 —— 动态新增的元素也自动生效，这是最高频的实战技巧。
  • preventDefault() 阻止默认行为：表单刷新、链接跳转、右键菜单。
  • input 每输入一个字符触发；change 要失焦才触发。
三个经典坑：
  1. 在循环里绑事件，回调里用到循环变量： 用 let 声明 i 就没问题；用 var 会导致所有回调 看到同一个最终值。更好的做法是直接用事件委托。
  2. 表单提交后页面刷新、数据没了：忘了 event.preventDefault()。
  3. 箭头函数里 this 不是当前元素： addEventListener("click", () => this) 里的 this 是外层作用域的，不是被点的元素。需要 this 就用 function；否则用 event.currentTarget 更清楚。
