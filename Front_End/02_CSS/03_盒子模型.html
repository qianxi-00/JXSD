CSS 盒子模型

盒子模型（Box Model）是 CSS 布局的地基。 页面上的每一个元素——无论是一个 <div>、一段 <p> 还是一个 <span>——在浏览器眼里都是一个矩形盒子。 理解了这个盒子由哪几层拼成，你就能回答下面这些高频问题：

  • 「我设了 width: 200px，为什么它实际占了 300px？」
  • 「为什么两个盒子的间距不是我以为的 60px，而是 30px？」
  • 「padding 和 margin 到底该用哪个？」

一、盒子的四层结构

课案用一张图说明了这个结构。下面这张图是用 CSS 现场画出来的（不是图片文件）， 由内到外一共四层：

margin 外边距
border 边框
padding 内边距
content 内容区
层次名称作用常用写法
1（最内） content 内容区 真正放文字、图片的地方。它的宽高由 width / height 决定 width: 200px;
2 padding 内边距 内容与边框之间的空白，在边框里面。背景色会铺到 padding 上 padding: 10px;
3 border 边框 盒子的边框线，有粗细、样式、颜色 border: 1px solid #ccc;
4（最外） margin 外边距 这个盒子与其他盒子之间的距离，在边框外面。背景色不会铺到 margin margin: 20px;

四边可以分别设置

/* 一个值：四边相同 */
padding: 10px;

/* 两个值：上下 / 左右 */
padding: 10px 20px;

/* 三个值：上 / 左右 / 下 */
padding: 10px 20px 30px;

/* 四个值：上 / 右 / 下 / 左（顺时针，从顶部开始） */
padding: 10px 20px 30px 40px;

/* 也可以单独指定某一边 */
padding-top: 10px;
margin-left: auto;      /* 左外边距自动 —— 右对齐常用技巧 */
记忆口诀：「上右下左，顺时针」，和钟表方向一致。 两个值记成「上下、左右」，和「先竖后横」一致。

二、盒子到底占多宽？（最容易踩的坑）

课案里的 padding、border、margin 究竟怎么影响尺寸？ 这是新手第一个大坑，我们用两个真实盒子做对比。

默认情况：box-sizing: content-box

.demo-box {
    width: 160px;           /* ← 这 160px 只是「内容区」的宽度！ */
    height: 80px;
    padding: 16px;          /* 左右各 16px，共 32px */
    border: 6px solid red;  /* 左右各 6px，共 12px */
    margin: 24px;           /* 左右各 24px，共 48px */
    box-sizing: content-box;   /* 默认值 */
}
层左右各累计计入宽度的值
content—160 px
padding16 px160 + 32 = 192 px
border6 px192 + 12 = 204 px ← 盒子自身宽度
margin24 px204 + 48 = 252 px ← 占用的总横向空间

视觉验证：下面斜纹底格子里那个蓝色盒子，代码里明明写的是 width: 160px， 但它看起来明显比 160px 宽——因为浏览器渲染的是 204px。

width:160px
content-box
这就是「我设了 width 但没用」的真相。 解决办法见下一节。

推荐做法：box-sizing: border-box

设置 box-sizing: border-box; 后，width 就表示 「内容区 + padding + border」的总宽度，算起来符合直觉。 同样的 width: 160px; padding: 16px; border: 6px， 现在盒子自身就是 160px 宽，浏览器会自动把内容区压成 160 - 32 - 12 = 116px。

width:160px
border-box

对比一下两个盒子：现在是一样宽的。

/* 现代 CSS 的第一条必备规则：让所有元素的宽度算法都变成 border-box */
*, *::before, *::after {
    box-sizing: border-box;
}
/* 这条规则几乎出现在每一个真实项目的第一行。
   注意：它必须写在最前面，因为后面的元素会继承这个「算法」而不是被覆盖。 */
一句话总结：
content-box（默认）：width 只管内容，加 padding/border 会越撑越大。
border-box（推荐）：width 管到底，加 padding/border 会向内挤压内容，总宽不变。
做「两个卡片各占 50% 并排」这类布局时，不用 border-box 几乎必然溢出换行。

三、padding 还是 margin？

padding 内边距margin 外边距
位置边框以内边框以外
背景色会被背景色/背景图覆盖不会被覆盖（永远是透明的）
可否为负不可以可以（常用于微调、负边距重叠）
点击区域算在元素内，可点击不算，点不到
典型用途让「内容」离边框远一点，例如按钮内文字不要贴边让「两个元素」离远一点，例如段落之间的间距

一句话判断：问自己「我要让内容离边框远点」→ padding； 「我要让这个盒子离别的盒子远点」→ margin。

margin 的两个经典陷阱

陷阱 1：外边距合并（margin collapse）

我是第一段，margin: 30px 0

我是第二段，margin: 30px 0

我是第三段，margin: 30px 0

上面三段之间看起来是 30px 而不是 60px！ 因为相邻的上下外边距会合并，取较大值，而不是相加。这是 CSS 规范里明确规定的行为。

  • 相邻兄弟元素的上下 margin 会合并。
  • 父元素与第一个/最后一个子元素的上下 margin 也会合并（导致"父元素高度塌陷"）。
  • 注意：只有上下会合并，左右不会。

怎么破：给父元素加 padding: 1px; 或 overflow: hidden;、 或 display: flex;（Flex 容器里的子元素不会发生外边距合并）。 实践中，现代布局基本都用 Flexbox，所以这个问题现在很少遇到了。

陷阱 2：行内元素的 margin/padding 表现异常

<span> 这类行内元素设 margin-top/bottom 是无效的， padding-top/bottom 虽然会画出背景，但不会撑开行高， 会盖到上下行上。结论：要给元素设置垂直间距，先确保它是块级元素 （display: block 或 inline-block）。

五、重点回顾

  • 每个元素都是一个盒子，由内到外：content → padding → border → margin。
  • padding 在边框内、会吃到背景色；margin 在边框外、永远透明。
  • 默认 box-sizing: content-box 时， 盒子自身宽度 = width + padding×2 + border×2；再加 margin 才是占位总宽。
  • 用 *, *::before, *::after { box-sizing: border-box; } 让宽度算法符合直觉， 这是现代 CSS 的第一条必备规则。
  • 相邻上下 margin 会合并取较大值（不是相加），左右不会。
  • 行内元素（span/a）设垂直 margin 无效，要设垂直间距先改成块级或 inline-block。
  • 调试盒子的最快方法：F12 → 选中元素 → Elements 面板底部会显示彩色的盒模型图， 悬停能高亮页面上的对应区域。
