## 一、集成学习总览：为什么"多个弱模型组合"能变强

### 1.1 一句话定义

集成学习（Ensemble Learning）不是只训练**一个**模型，而是训练**多个弱模型**，再按某种规则把它们
组合成一个**更强的模型**。

> 单个模型的问题：要么太简单（学不到规律，偏差大），要么太复杂（把噪声也背下来了，方差大）。
> 集成学习的思路：既然一个模型总会在某个方向上犯错，那就训练一批模型，
> 让它们的错误**互相抵消**，保留它们共同抓到的真实规律。

### 1.2 从偏差—方差分解看"为什么能变强"

对平方损失，一个模型在样本 $x$ 上的期望泛化误差可以精确分解为三项：

$$
\mathbb{E}\big[(y - \hat{f}(x))^2\big]
= \underbrace{\big(\mathbb{E}[\hat{f}(x)] - f(x)\big)^2}_{\text{偏差}^2\ \mathrm{Bias}^2}
+ \underbrace{\mathbb{E}\big[(\hat{f}(x) - \mathbb{E}[\hat{f}(x)])^2\big]}_{\text{方差}\ \mathrm{Var}}
+ \underbrace{\sigma^2_{\varepsilon}}_{\text{不可约噪声}}
$$

- **偏差（Bias）**：模型平均预测与真实规律差多远 —— 反映"模型能力够不够"。
  模型太简单（如线性模型拟合非线性数据）→ 偏差大 → **欠拟合**。
- **方差（Variance）**：模型在不同训练集上预测的波动有多大 —— 反映"模型对数据有多敏感"。
  模型太复杂（如不剪枝的深树）→ 方差大 → **过拟合**。
- **不可约噪声**：数据本身的随机性，任何模型都无法消除，是误差的下限。

**集成的核心作用就是压低方差、或者压低偏差。**

#### 为什么"取平均"能压方差

假设有 $M$ 个**相互独立**、方差同为 $\sigma^2$ 的模型，把它们简单平均：

$$
\mathrm{Var}\left(\frac{1}{M}\sum_{m=1}^{M}\hat{f}_m(x)\right)
= \frac{1}{M^2}\sum_{m=1}^{M}\mathrm{Var}\big(\hat{f}_m(x)\big)
= \frac{\sigma^2}{M}
$$

方差被压到原来的 $1/M$，而**均值不变**（所以偏差几乎不变）。这就是 Bagging 的数学根据。

现实中模型不可能完全独立，设两两相关系数为 $\rho$，则更一般的结论是：

$$
\mathrm{Var}\left(\frac{1}{M}\sum_{m=1}^{M}\hat{f}_m(x)\right)
= \rho\,\sigma^2 + \frac{1-\rho}{M}\,\sigma^2
$$

这个式子给出两条极有价值的工程结论：

1. $M$ 变大时，第二项 $ \frac{1-\rho}{M}\sigma^2 \to 0$，但**第一项 $\rho\sigma^2$ 是天花板**。
   所以"树的数量"加到一定程度后收益就饱和了 —— 随机森林里 500 棵树和 1000 棵树差别很小。
2. **降低相关性 $\rho$ 比增加数量 $M$ 更重要。** 这正是随机森林要做
   "样本自助采样 + 特征随机子集"的原因：人为地让每棵树看到不同的数据、不同的特征，
   把 $\rho$ 压下来，才能把方差压得更低。

#### Boosting 走的是另一条路：压偏差

Boosting 不追求"独立"，恰恰相反，它**故意让每棵树高度相关**（每棵都在修正同一批错误），
所以它几乎不降低方差，而是通过**不断叠加弱模型、持续逼近残差**来把**偏差**压下去。

- 单个浅树（depth=3）是**高偏差、低方差**的弱学习器 —— 它自己学不好，但很稳定。
- Boosting 把几百个这样的弱学习器串起来，每一步都补一点残差，
  偏差被一步步抹掉，最终得到一个低偏差的强模型。
- 代价是：因为树之间强相关且不断拟合残差，**方差不会被压下去**，
  甚至会被噪声放大 —— 树太多时测试误差回升（我们 `01_GBDT.py` 里的曲线就是证据）。

### 1.3 一张图理解两大流派

```
                       集成学习
                          │
        ┌─────────────────┴─────────────────┐
        │                                   │
   Bagging（并行）                     Boosting（串行）
   多个模型独立训练，投票/平均          多个模型依次训练，逐个纠错
        │                                   │
   ┌────┴────┐                     ┌────────┼────────┬─────────┐
 随机森林  ExtraTrees             AdaBoost   GBDT   XGBoost  LightGBM
        │                                   │
   主要降【方差】                      主要降【偏差】
   基学习器：强（深树）                基学习器：弱（浅树）
   抗噪声：较强                        抗噪声：较弱
```

### 1.4 组合策略

| 组合方式 | 公式 | 适用任务 | 代表 |
|---|---|---|---|
| 投票法（Voting） | 分类：$\hat{y}=\arg\max_c \sum_m \mathbb{1}[h_m(x)=c]$ | 分类 | 随机森林（硬投票）、VotingClassifier |
| 平均法（Averaging） | 回归：$\hat{y}=\frac{1}{M}\sum_m h_m(x)$ | 回归 | 随机森林回归 |
| 加权平均 | $\hat{y}=\sum_m \alpha_m h_m(x),\ \sum_m\alpha_m=1$ | 回归/分类 | AdaBoost 的样本权重 |
| 加法模型（Additive） | $F_M(x)=F_0(x)+\eta\sum_m f_m(x)$ | 回归/分类 | **GBDT / XGBoost / LightGBM** |
| 堆叠（Stacking） | 用第二层模型学习"如何组合第一层" | 通用 | StackingClassifier |

> **本文后面的三节只讲加法模型这一支**（GBDT → XGBoost → LightGBM），因为它们是课案的重点。

## 二、Bagging vs Boosting 全面对比

| 对比维度 | Bagging（装袋） | Boosting（提升） |
|---|---|---|
| **采样方式** | 有放回自助采样（bootstrap）：每棵树用一份不同的、约 63.2% 的样本 | 每轮用**全部**样本，但样本的**权重/梯度**不同；后续树重点关注前面预测错的样本 |
| **样本权重** | 各样本等权，采样过程本身引入差异 | 动态调整：错得越多，权重/梯度越大 |
| **训练方式** | **并行**：各基学习器相互独立，可同时训练 | **串行**：第 $m$ 个模型依赖前 $m-1$ 个模型的结果，必须按顺序训练 |
| **基学习器强弱** | 强学习器（深树、不剪枝、低偏差高方差） | 弱学习器（浅树 depth 3~8、高偏差低方差） |
| **主要降低** | **方差**（Variance） | **偏差**（Bias） |
| **对偏差的影响** | 几乎不变（平均不改变期望） | 显著降低（持续拟合残差） |
| **对异常值/噪声的敏感度** | **较低**：投票/平均能把个别树的错误平滑掉 | **较高**：噪声会被当作"还没学好的残差"反复拟合，越训练越严重 |
| **树的数量增加时** | 收益很快饱和（方差下界为 $\rho\sigma^2$），不会过拟合 | 训练误差持续下降，但**测试误差会先降后升**（过拟合），必须早停 |
| **代表算法** | 随机森林（Random Forest）、ExtraTrees、Bagged Trees | AdaBoost、GBDT、XGBoost、LightGBM、CatBoost |
| **典型学习率参数** | 无（每棵树权重相同） | 有（$\eta$ / shrinkage，控制每棵树的修正力度） |
| **是否容易并行** | 天然并行（`n_jobs` 直接生效） | 树与树串行；只有"单棵树内部找分裂点"能并行 |
| **调参难度** | 低（主要就 `n_estimators` + `max_depth`），默认参数往往就够用 | 高（学习率、树数、树深、采样、正则化彼此联动） |

**一句话选择口诀：**

> 数据噪声大、想要"开箱即用不容易出错" → **随机森林**（Bagging）。
> 追求极致精度、愿意花时间调参 → **Boosting**（GBDT / XGBoost / LightGBM）。

## 三、Boosting 的统一加法模型与前向分步算法

### 3.1 加法模型（Additive Model）

GBDT、XGBoost、LightGBM 都属于 Boosting 家族，它们共享同一个骨架 —— **加法模型**：

$$
\boxed{\;F_0(x)=\arg\min_{c}\sum_{i=1}^{N}L\big(y_i,\,c\big)\;}
$$

$$
\boxed{\;F_m(x)=F_{m-1}(x)+\eta\, f_m(x),\qquad m=1,2,\dots,M\;}
$$

$$
\boxed{\;F_M(x)=F_0(x)+\eta\sum_{m=1}^{M}f_m(x)\;}
$$

> **模型不是一步到位学出来的。**
> 而是先有一个初始答案 $F_0$，再一轮一轮地加上小模型 $f_m$ 去修正错误。

### 3.2 符号表

| 符号 | 含义 | 大白话解释 | 对应 API 参数 |
|---|---|---|---|
| $F_0(x)$ | 初始模型（基础预测） | 一开始先给一个最粗糙的答案，比如全体样本的最优常数、分类任务里的先验对数几率 | `init_` / `base_score` |
| $f_m(x)$ | 第 $m$ 个弱模型 | 当前这一轮用来"补错误"的小模型（通常是一棵深度 3 左右的回归树） | 每棵树的 `tree_` |
| $\eta$ | 学习率 / 收缩系数（shrinkage） | 每次修正的力度，只允许补一点点，防止一次改过头 | `learning_rate` |
| $M$ | 弱模型数量 | 一共训练多少轮、多少棵树 | `n_estimators` |
| $F_M(x)$ | 最终模型 | 多轮修正后得到的最终预测结果 | 训练完的模型对象 |
| $N$ | 样本数量 | 有多少条训练数据 | `X.shape[0]` |
| $L(y,\hat y)$ | 损失函数 | 预测错了要付出的代价，决定"负梯度长什么样" | `loss` / `objective` |
| $\eta f_m(x)$ | 第 $m$ 轮的增量 | 这一轮模型"进步"了多少 | —— |

### 3.3 前向分步算法（Forward Stagewise Algorithm）

**问题**：加法模型要同时优化 $M$ 个函数 $f_1,\dots,f_M$ 和 $\eta$，这是一个巨大的联合优化问题，没法直接解。

**前向分步算法的解法**：把它拆成 $M$ 个**小优化问题**，一个一个解。

初始化 $F_0(x)$ 后，对 $m=1,2,\dots,M$ 循环执行：

$$
(\eta,\,f_m)=\arg\min_{\eta,\,f}\sum_{i=1}^{N}
L\Big(y_i,\;F_{m-1}(x_i)+\eta\, f(x_i)\Big)
$$

**关键理解**：这个 $\arg\min$ **只作用在"当前这一个 $f$ 和 $\eta$"上**，
前面已经训练好的 $F_{m-1}$ 被当成**已知常数冻结**，不回头修改。

> 这正是 Boosting 能"一轮一轮做下去"的原因：每一轮只是一个小优化问题，容易求解。
> 也正是它**必须串行**的原因：第 $m$ 轮的目标依赖第 $m-1$ 轮的输出，
> 不给 $F_{m-1}$ 就算不出第 $m$ 轮要拟合什么。

**算法流程：**

```
输入：训练集 {(x_i, y_i)}_{i=1..N}，损失函数 L，学习率 η，轮数 M
──────────────────────────────────────────────────────
1. 初始化 F_0(x) = argmin_c Σ L(y_i, c)          # 猜一个最好的常数
2. for m = 1 to M:
   a. 计算每个样本的"负梯度"（伪残差）
        r_{im} = -[ ∂L(y_i, F(x_i)) / ∂F(x_i) ] |_{F = F_{m-1}}
   b. 用回归树去拟合这一批 r_{im}，得到第 m 棵树 f_m(x)
   c. 更新模型：  F_m(x) = F_{m-1}(x) + η · f_m(x)
3. 输出最终模型 F_M(x)
──────────────────────────────────────────────────────
```

### 3.4 为什么"负梯度"就是修正方向

把损失在第 $m$ 轮做一阶泰勒展开（$F_{m-1}(x_i)$ 是常数）：

$$
L\big(y_i,\;F_{m-1}(x_i)+f(x_i)\big)\;\approx\;
L\big(y_i,F_{m-1}(x_i)\big)+f(x_i)\cdot
\underbrace{\frac{\partial L(y_i,F(x_i))}{\partial F(x_i)}\Bigg|_{F=F_{m-1}}}_{\text{梯度}}
$$

要让损失**变小**，就应该让 $f(x_i)$ 沿着**负梯度**方向取值：

$$
f_m(x_i)\;\approx\;-\,\frac{\partial L(y_i,F(x_i))}{\partial F(x_i)}\Bigg|_{F=F_{m-1}}
$$

这个量就叫 **负梯度**，也叫 **伪残差（pseudo-residual）**。

| 任务 | 损失函数 | 负梯度 $-\partial L/\partial F$ | 直观含义 |
|---|---|---|---|
| 回归 | $L=\frac{1}{2}(y-F)^2$ | $y-F_{m-1}(x)$ | **就是普通残差**（真实值 − 当前预测值） |
| 二分类 | $L=-\big[y\ln p+(1-y)\ln(1-p)\big],\ p=\sigma(F)$ | $y-p$ | 概率残差（标签 0/1 减去预测概率） |
| 多分类 | 交叉熵 | $y_k-p_k$ | 每个类别的概率残差 |

> 所以"GBDT 用负梯度拟合新树"在**回归任务里就是"用残差拟合新树"**，
> 在分类任务里是"用概率残差拟合新树"。两者形状一样，只是分类的残差是概率尺度。

### 3.5 一个数值例子（感受"加法"）

设真实值 $y=100$，$\eta=0.8$：

| 轮次 | 当前预测 $F_{m-1}$ | 残差 $y-F_{m-1}$ | 本轮补偿 $\eta f_m$ | 新预测 $F_m$ |
|---|---|---|---|---|
| 0 | 60（全体均值） | 40 | — | 60 |
| 1 | 60 | 40 | $0.8\times40=32$ | 92 |
| 2 | 92 | 8 | $0.8\times8=6.4$ | 98.4 |
| 3 | 98.4 | 1.6 | 1.28 | 99.68 |
| … | … | 越来越小 | … | → 100 |

每棵树都很弱（只会补一点点），但很多棵树叠加起来就逼近了真实答案。
$\eta$ 就是"每次只补几成"这个折扣系数。

## 四、GBDT：用负梯度（残差）拟合新树

**GBDT = Gradient Boosting Decision Tree**，即"梯度提升决策树"。

> **GBDT** 不是一次性训练一棵很强的树，而是不断训练很多棵小树。
> 后一棵树专门去弥补前一棵树犯的错误。最后把多棵树的结果加起来，得到最终预测结果。

### 4.1 核心思想（课案原文的表格，重写）

第 $m$ 棵树不是直接学习真实答案 $y$，而是学习上一轮模型的**残差**（预测值和真实值之间的差距）：

| 符号 | 含义 | 大白话解释 |
|---|---|---|
| $F_{m-1}(x)$ | 上一轮模型的预测结果 | 当前已经预测到多少分 |
| $y-F_{m-1}(x)$ | 残差（回归任务） | 还差多少分 |
| $f_m(x)$ | 第 $m$ 棵树 | 这一轮用来补错误的小树 |
| $\eta$ | 学习率 | 每次修正的力度 |
| $F_m(x)=F_{m-1}(x)+\eta f_m(x)$ | 更新后的模型 | 修正后的新预测结果 |

**GBDT 的完整算法：**

1. 初始化 $F_0(x)=\arg\min_c\sum_i L(y_i,c)$
   —— 回归用均方误差时就是 $\bar y$；二分类用对数损失时是 $\ln\frac{\bar y}{1-\bar y}$（先验对数几率）。
2. 对 $m=1,\dots,M$：
   - 计算伪残差 $r_{im}=-\big[\partial L(y_i,F(x_i))/\partial F(x_i)\big]_{F=F_{m-1}}$；
   - 用回归树拟合 $\{(x_i,r_{im})\}_{i=1}^{N}$，得到叶子区域 $R_{jm}\ (j=1,\dots,J_m)$；
   - 对每个叶子求一个最优输出值（线搜索）：
     $\gamma_{jm}=\arg\min_\gamma\sum_{x_i\in R_{jm}}L\big(y_i,F_{m-1}(x_i)+\gamma\big)$；
   - 更新 $F_m(x)=F_{m-1}(x)+\eta\sum_j\gamma_{jm}\mathbb{1}[x\in R_{jm}]$。
3. 输出 $F_M(x)$。

### 4.2 直观例子：把 GBDT 想成"考试提分"

> 课案里的"GBDT 考试分数例子"就是这个道理。

假设一个学生要考到 **100 分**，他不可能一次到位：

- **第 0 轮**：先按全班平均分估一个 **60 分** —— 这就是 $F_0$。差 **40 分**。
- **第 1 轮**：老师针对"还差的 40 分"给了一套专项练习（第 1 棵树）。
  但老师知道一次补太猛容易矫枉过正，只让他补 8 成 → 提了 **32 分** → 现在 **92 分**。还差 8 分。
- **第 2 轮**：针对"还差的 8 分"再给一套练习，还是只补 8 成 → 提了 **6.4 分** → 现在 **98.4 分**。
- **第 3 轮**：再补 → **99.68 分**。
- ……每一轮都针对"当前还差多少"做专项训练，差距被一轮一轮擦掉。

**映射关系：**

| 考试比喻 | 算法符号 | 对应含义 |
|---|---|---|
| 全班平均分 | $F_0(x)$ | 初始模型 |
| "还差多少分" | $y-F_{m-1}(x)$ | 残差 / 负梯度 |
| 每一轮专项练习 | $f_m(x)$ | 第 $m$ 棵回归树 |
| "只补 8 成" | $\eta$ | 学习率（shrinkage） |
| 练习次数 | $M$ | `n_estimators` |
| 最终成绩 | $F_M(x)$ | 最终模型 |

**这套比喻还能解释三件事：**

1. **为什么学习率小就要更多轮**：每次只补 5 成（$\eta=0.05$），自然要比补 10 成走更多轮才能到 100 分。
2. **为什么会过拟合**：如果这个学生本来就该考 95 分（那 5 分是题目本身的随机性/噪声，谁也拿不到），
   老师却一直逼他补到 100 分，他就开始"背答案"了 —— 这就是把噪声当残差学。
3. **为什么要早停**：练到某个次数后，练得越多考得越差，最优点之后就该停下。

### 4.3 GBDT 与随机森林的区别

| 算法 | 多棵树之间的关系 | 核心思想 | 组合方式 | 基学习器 | 主要降低 |
|---|---|---|---|---|---|
| **随机森林** | 多棵树**并行**训练 | 大家一起投票 | 平均/投票 | 深树（强学习器） | 方差 |
| **GBDT** | 多棵树**串行**训练 | 后一棵树修正前一棵树的错误 | 带学习率的加法累加 | 浅树（弱学习器） | 偏差 |

**更细一点的区别：**

| 维度 | 随机森林 | GBDT |
|---|---|---|
| 训练数据 | 每棵树用一份 bootstrap 样本 | 每棵树用全部样本（或 `subsample` 抽样），但拟合目标不同 |
| 拟合目标 | 原始标签 $y$ | 负梯度/伪残差 $r_{im}$ |
| 树的数量增加 | 收益饱和，**不会过拟合** | 会过拟合，**必须早停** |
| 并行性 | 完全并行，加机器线性能加速 | 树之间串行，只能并行"单树内部找分裂点" |
| 对噪声 | 不敏感 | 敏感 |
| 典型参数 | `n_estimators`、`max_depth`、`max_features` | 上述 + `learning_rate`、`subsample`、早停 |
| 缺失值 | 需手动处理 | sklearn 的 GBDT 也不支持 NaN（要 XGBoost/LightGBM 才自动处理） |

### 4.4 sklearn 的关键参数（`GradientBoostingClassifier`）

| 参数 | 默认值 | 作用与调参方向 |
|---|---|---|
| `loss` | `'log_loss'` | 损失函数，决定负梯度的形状。`'log_loss'`（旧名 `'deviance'`）二/多分类通用；`'exponential'` 即 AdaBoost 的指数损失，只适合二分类 |
| `learning_rate` | `0.1` | 收缩系数 $\eta$。**与 `n_estimators` 联动**：减半则树数大致翻倍 |
| `n_estimators` | `100` | 树的数量 $M$。配合早停自动确定 |
| `max_depth` | `3` | 单树最大深度，**最重要的复杂度旋钮**，常用 3~8 |
| `min_samples_leaf` | `1` | 叶子最少样本数，调大（5~50）抗过拟合 |
| `subsample` | `1.0` | 行采样比例，取 0.7~0.9 即"随机梯度提升"，提速 + 降方差 |
| `max_features` | `None` | 每次分裂考虑的特征比例，可设 `'sqrt'` 或 0.8 |
| `validation_fraction` | `0.1` | 从训练集内部切出的验证集比例，**仅在早停时使用** |
| `n_iter_no_change` | `None` | 早停耐心值（如 20），`None` 表示不早停 |
| `tol` | `1e-4` | 早停阈值：改善幅度小于它就算"没进步" |
| `criterion` | `'friedman_mse'` | 回归树分裂准则，与负梯度推导更匹配，一般不改 |

> ⚠️ **`GradientBoostingClassifier` 没有正则项参数**（没有 `reg_lambda`、`gamma`）。
> 它控制复杂度只能靠 `max_depth` / `min_samples_leaf` / `learning_rate` / `subsample`。
> 这是 XGBoost / LightGBM 在正式场景中更受欢迎的原因之一。
>
> ⚠️ **树模型不需要标准化**：分裂只比较特征取值的大小顺序，Z-score 或 Min-Max 不改变任何分裂点。

## 五、XGBoost：把正则化写进目标函数

**XGBoost = eXtreme Gradient Boosting**，可以理解为 **GBDT 的加强版 / 工程优化版**。

> XGBoost 仍然是一棵树一棵树地往后训练，后一棵树还是去修正前面模型的错误。
> 但它在 GBDT 的基础上加入了更多优化，让模型更快、更稳，也更不容易过拟合。

与 GBDT 的核心差别：

| 算法 | 核心特点 |
|---|---|
| GBDT | 用后一棵树修正前一棵树的错误（只用损失函数） |
| XGBoost | **加入正则化和工程加速优化**（损失函数 + 显式正则项 + 二阶信息 + 并行找分裂点） |

> 核心思想：还是用很多棵树按顺序学习。不同的是，XGBoost 不只看"错误往哪个方向改"，
> 还会考虑"**改多少更合适**"（二阶展开解出最优叶子权重），并且会限制树不要长得太复杂（正则项）。

### 5.1 名词介绍（课案表格）

| 名词 | 含义 | 大白话解释 | 相关参数 |
|---|---|---|---|
| 正则化 | 对复杂模型进行惩罚 | 树太复杂就扣分，防止死记硬背 | `reg_lambda`、`reg_alpha`、`gamma` |
| 剪枝 | 去掉贡献不大的树枝 | 没有明显帮助的分裂就不要了 | `gamma`、`max_depth` |
| 缺失值处理 | 自动学习缺失值该走哪个方向 | 数据里有空值时，不一定要先手动填充 | 自动完成 |

### 5.2 核心目标函数

XGBoost 的核心目标函数由两部分组成：**预测损失 + 模型复杂度惩罚**。

$$
\boxed{\;\mathrm{Obj}=\sum_{i=1}^{N} l\big(y_i,\hat y_i\big)\;+\;\sum_{m=1}^{M}\Omega\big(f_m\big)\;}
$$

其中正则化项为：

$$
\boxed{\;\Omega(f)=\gamma T+\frac{1}{2}\lambda\sum_{j=1}^{T}w_j^{2}\;}
$$

| 符号 | 含义 | 大白话解释 |
|---|---|---|
| $l(y_i,\hat y_i)$ | 损失函数 | 预测错了要付出的代价 |
| $f_m$ | 第 $m$ 棵树 | 当前这一轮用来补错误的小树 |
| $\Omega(f_m)$ | 正则化项 | 对复杂树的惩罚 |
| $T$ | 叶子节点数量 | 树有多少个最终分支 |
| $w_j$ | 第 $j$ 个叶子的权重 | 这个叶子给预测结果加多少分 |
| $\gamma,\ \lambda$ | 正则化参数 | $\gamma$ 惩罚"叶子太多"，$\lambda$ 惩罚"叶子权重太大" |
| $\mathrm{Obj}$ | 总目标函数 | 错误要小，模型也不能太复杂 |

> 这个公式可以理解为：XGBoost 不只是追求预测错误小，它还希望模型结构简单，
> 不要为了训练集上的一点点提升，把树长得特别复杂。

### 5.3 二阶泰勒展开：推导最优叶子权重

第 $m$ 轮时，前面的 $F_{m-1}$ 已经固定，待求的是本轮新增的树 $f_m$。
把损失在 $\hat y=F_{m-1}(x_i)$ 处做**二阶**泰勒展开（GBDT 只用到一阶，这是关键升级）：

$$
\mathrm{Obj}^{(m)}\approx\sum_{i=1}^{N}\Big[
\underbrace{l\big(y_i,F_{m-1}(x_i)\big)}_{\text{常数，可忽略}}
+g_i f_m(x_i)+\frac{1}{2}h_i f_m(x_i)^2\Big]
+\gamma T+\frac{1}{2}\lambda\sum_{j=1}^{T}w_j^{2}
$$

其中一阶导与二阶导分别为：

$$
g_i=\frac{\partial l(y_i,\hat y)}{\partial \hat y}\Bigg|_{\hat y=F_{m-1}(x_i)},
\qquad
h_i=\frac{\partial^2 l(y_i,\hat y)}{\partial \hat y^{2}}\Bigg|_{\hat y=F_{m-1}(x_i)}
$$

| 损失 | $g_i$ | $h_i$ |
|---|---|---|
| 平方损失 $\frac12(y-\hat y)^2$ | $\hat y-y$ | $1$ |
| 二分类对数损失 | $p_i-y_i$ | $p_i(1-p_i)$ |
| Softmax 多分类 | $p_{ik}-y_{ik}$ | $2p_{ik}(1-p_{ik})$ |

因为**同一棵树里落在同一个叶子的样本共享同一个输出值** $w_j$，
把样本按叶子分组（$I_j$ 表示第 $j$ 个叶子的样本集合）后，目标函数变成：

$$
\mathrm{Obj}^{(m)}\approx\sum_{j=1}^{T}\Big[
\underbrace{\Big(\sum_{i\in I_j}g_i\Big)}_{G_j}w_j
+\frac{1}{2}\underbrace{\Big(\sum_{i\in I_j}h_i+\lambda\Big)}_{H_j+\lambda}w_j^{2}\Big]
+\gamma T
$$

记 $G_j=\sum_{i\in I_j}g_i$（叶子内一阶梯度和）、$H_j=\sum_{i\in I_j}h_i$（叶子内二阶梯度和）。
这是一个关于 $w_j$ 的**开口向上的抛物线**，直接令导数为 0 即可解出**最优叶子权重**：

$$
\frac{\partial\,\mathrm{Obj}}{\partial w_j}=G_j+(H_j+\lambda)w_j=0
\quad\Longrightarrow\quad
\boxed{\;w_j^{*}=-\frac{G_j}{H_j+\lambda}\;}
$$

> **XGBoost 不需要对叶子权重做梯度下降**，一步解析解就出来了 —— 这是二阶展开带来的最大便利。
> 分母上的 $\lambda$ 会把权重压小：$\lambda$ 越大，单棵树越保守。

把 $w_j^*$ 代回，得到"这棵树能带来的最小损失"（也是"纯度"的度量）：

$$
\mathrm{Obj}^{(m)*}=-\frac{1}{2}\sum_{j=1}^{T}\frac{G_j^{2}}{H_j+\lambda}+\gamma T
$$

### 5.4 分裂增益公式：Gain > 0 才值得分

假设某个叶子节点分裂成左 $L$、右 $R$ 两半，用"分裂前的分数 − 分裂后的分数"作为收益：

$$
\boxed{\;
\mathrm{Gain}=\frac{1}{2}\left[
\frac{G_L^{2}}{H_L+\lambda}+\frac{G_R^{2}}{H_R+\lambda}
-\frac{(G_L+G_R)^{2}}{H_L+H_R+\lambda}
\right]-\gamma\;}
$$

**结构解读：**

$$
\mathrm{Gain}=\underbrace{\text{分裂后左右两边的"纯度提升"}}_{\ge 0}
-\underbrace{\gamma}_{\text{分裂的"手续费"}}
$$

- 前半部分**恒为非负**：分裂总不会让损失变大（这是二阶近似的性质）。
- 减去 $\gamma$ 之后 $\mathrm{Gain}$ 可能 $\le 0$，那就"**不值得分**"，这个分裂被否决 —— 这就是 $\gamma$ 剪枝。
- $\lambda$ 出现在三个分母里：$\lambda$ 越大，各叶子的权重越小，分裂收益也越平缓、越难超过 $\gamma$。

**XGBoost 找分裂点的完整流程：**

```
对当前节点的每个特征 j:
    把样本按特征 j 的取值排序
    从左到右扫描，维护 G_L/H_L 和 G_R/H_R
    对每个候选切分点计算 Gain
选 Gain 最大的那个 (特征, 切分点)：
    若 max Gain <= 0（严格说 <= gamma）→ 不分裂，该节点成为叶子
    否则分裂，并把 w_L*, w_R* 作为两个新叶子的输出
```

### 5.5 工程优化细节

| 优化 | 作用 |
|---|---|
| **列采样** `colsample_bytree` / `colsample_bylevel` / `colsample_bynode` | 每棵树（或每层/每节点）只用一部分特征找分裂点。既加速，又像随机森林那样**降低方差** |
| **行采样** `subsample` | 每棵树只用一部分样本，进一步抗过拟合（随机梯度提升） |
| **缺失值自动方向** | 分裂时分别尝试"缺失样本全走左"和"全走右"，取 Gain 更大的一种，并把**默认方向**记录在树里。所以有 NaN 时**不需要先手工填充** |
| **加权分位数草图**（`tree_method='approx'`） | 不精确枚举每个取值，而是以 $h_i$ 作为权重挑候选分裂点，大幅降低计算量 |
| **预排序 + 块结构（Block）** | 训练前把每列特征排序并压缩成块，找分裂点时复用排序结果、支持缓存友好的列式访问 |
| **直方图算法**（`tree_method='hist'`） | 把特征分桶，遍历桶而非遍历样本，是当前默认推荐的高效模式 |
| **稀疏感知（sparse-aware）** | 只遍历非缺失值，对稀疏数据（one-hot 后的文本特征）非常高效 |
| **缓存优化 + 核外计算** | 预取梯度到缓存、数据太大时切块从磁盘读，支持超大规模数据 |

### 5.6 XGBoost 的并行到底并行在哪里（重点）

先明确一个前提：

> XGBoost 依然是 **Boosting** 算法，所以它依旧是一棵一棵树逐步计算损失。
> 第 $m$ 棵树要拟合第 $m-1$ 轮算出来的 $g_i,h_i$，**树与树之间必定只能串行**。

那并行在哪里？

> **XGBoost 的并行主要发生在"训练每一棵树"的内部。**
> 也就是说：**树和树之间不能并行；一棵树里面可以并行。**

训练一棵决策树时，模型要做很多判断：

- 哪个特征最适合分裂？
- 哪个切分点最好？
- 分裂之后损失下降多少？

比如现在有 100 个特征，普通做法可能是一个一个看，XGBoost 可以并行计算：

```
线程1：计算特征 1-20
线程2：计算特征 21-40
线程3：计算特征 41-60
线程4：计算特征 61-80
线程5：计算特征 81-100
                    ↓
最后汇总：哪个特征、哪个切分点让损失下降最多
```

> 所以 XGBoost 的并行是：**并行寻找"当前这一棵树"的最佳分裂点。**

**再深一层**：预排序 + Block 结构让"找分裂点"这一步变成一次**线性扫描**。
每个特征列的排序结果预先算好并且可复用（同一个特征在不同树、不同层上不用重新排序），
多线程按**特征列**切分任务，各自扫描自己的列算出 $G_L,G_R$ 和 Gain，最后取全局最大 ——
这是"列并行"（column-parallel）的实现方式。

> 也正因为并行粒度是"特征列"而不是"树"，增加线程数只能加快单棵树的构建速度，
> **不会改变 boosting 串行的总轮数**。所以 XGBoost 的多核加速比通常达不到线性。

### 5.7 剪枝：`gamma` 控制最小分裂增益

XGBoost 的剪枝有**两种**：

1. **预剪枝（pre-pruning）**：分裂前检查 $\mathrm{Gain}$ 是否 $>\gamma$（严格说是 $\ge$）。
   不满足就不分裂，该节点直接成为叶子。
2. **后剪枝（post-pruning）**：先把树长到 `max_depth`，再从**叶子往上**递归检查：
   如果某个节点的分裂收益 $<\gamma$，就把这个分裂**撤销**，让它退化成叶子。
   （XGBoost 的 `gamma` 两种都会用到效果。）

$\gamma$ 的实际影响：

| `gamma` | 效果 |
|---|---|
| 0（默认） | 只要 $\mathrm{Gain}>0$ 就分裂，树自由生长 |
| 0.1 ~ 1 | 轻微剪枝，剪掉收益微弱的分裂 |
| 1 ~ 5 | 明显剪枝，树的叶子数显著减少（我们的 `02_XGBoost.py` 里 gamma=5 时叶子总数从 1828 降到 601） |
| 20+ | 过度剪枝，模型开始**欠拟合**（gamma=20 时测试 AUC 掉到 0.925） |

> 记忆点：$\gamma$ 就是"**分裂的手续费**"。手续费越高，只有越划算的分裂才被允许，
> 树自然长得越浅、越少。而且因为目标函数里有 $+\gamma T$ 这一项，
> **叶子数 $T$ 越多，被罚得越狠** —— 这本身就是一种自动的复杂度控制。

### 5.8 xgboost 3.x sklearn 接口的注意事项

```python
from xgboost import XGBClassifier

model = XGBClassifier(
    n_estimators=1000,
    learning_rate=0.05,
    max_depth=4,
    eval_metric="logloss",
    early_stopping_rounds=30,   # ← 注意：写在构造函数里（xgboost 3.x）
    tree_method="hist",
    random_state=42,
    n_jobs=2,
    verbosity=0,                # ← 静默，不打印 C 层日志
)

model.fit(
    X_train, y_train,
    eval_set=[(X_val, y_val)],  # ← 验证集写在 fit 里
    verbose=False,              # ← 关闭"每轮打印一行"
)

model.best_iteration            # 从 0 开始，实际树数 = best_iteration + 1
model.best_score                # 验证集最优分数（由 eval_metric 决定含义）
```

**三个坑：**

1. ❌ **不要手写 `objective="multi:softmax"` + `num_class=3`**。
   sklearn 包装器会根据 `y` **自动推断** `objective` 和类别数，手动传会与之冲突或产生告警。
   课案里的示例代码是**原生接口**的写法，用 sklearn 包装器时应当省略这两个参数。
2. ✅ **`early_stopping_rounds` 要写在构造函数里**，不是 `fit()` 的参数
   （旧版本的写法会报错或告警）。
3. ✅ **`best_iteration` 是从 0 开始的轮序号**，人话表述要 `+1`（即 `best_iteration + 1` 棵树）。

## 六、LightGBM：直方图 + Leaf-wise

**LightGBM = Light Gradient Boosting Machine**，也是一种基于 GBDT 思想的集成学习算法。

> LightGBM 还是一棵树一棵树地训练，后一棵树继续修正前面模型的错误。
> 但它更强调**训练速度**和**大规模数据处理能力**，特别适合数据量比较大的场景。

### 6.1 与 XGBoost 的定位对比

| 算法 | 核心特点 | 大白话理解 |
|---|---|---|
| XGBoost | 稳定、通用、正则化强 | 加强版 GBDT，比较稳 |
| LightGBM | 训练快、占内存少 | 更轻、更快，适合大数据 |

> 核心思想：LightGBM 仍然是 Boosting，但它用**直方图算法**和**叶子优先生长**策略来加速训练。
> 它不是每一层都整齐地长树，而是**优先分裂收益最大的叶子**。

### 6.2 直方图算法（LightGBM 快的秘诀之一）

XGBoost 的 exact 模式找分裂点需要"逐个样本"排序、枚举每一个取值。
LightGBM 先把连续特征**离散化**装进固定数量的"桶"里（默认 `max_bin = 255`）：

```
年龄特征:  0~18 | 18~30 | 30~45 | 45~60 | 60+
            桶0     桶1     桶2     桶3    桶4
            ↑ 每个桶只记三样东西：桶里有多少样本、G 加总、H 加总
```

之后找分裂点**只遍历桶（比如 255 个），不遍历每一个样本**：

$$
\text{复杂度：}\quad O(\#\text{样本}\times\#\text{特征})
\;\longrightarrow\;
O(\#\text{桶}\times\#\text{特征}),\qquad \#\text{桶}=255\ \text{是常数}
$$

**为什么"数据量越大加速越明显"？**
因为桶的数量是**常数**，样本数量是**变量**。
1000 行数据时两者差别不大（甚至桶的构建开销占主导），
100 万行时"数 255 个桶"和"数 100 万个样本"就是数量级的差距。

| 收益 | 代价 |
|---|---|
| 速度快（复杂度与样本数解耦） | 特征被离散化，理论上损失一点点精度（实践中几乎看不出来） |
| 内存省（只存桶编号，通常 8 位整数，不用存原始浮点） | `max_bin` 调太小会损失精度 |
| 天然支持类别特征、支持并行/分布式 | —— |

**两个进一步的提速技术（了解即可）：**

- **GOSS（Gradient-based One-Side Sampling，基于梯度的单边采样）**
  梯度大的样本说明"还没学好"，**全部保留**；梯度小的样本（已经学好）**随机丢弃一部分**。
  这样用一部分样本就能较准确地估计分裂增益，进一步提速。
  设置方式：`boosting_type='goss'`（此时 `subsample` 必须为 1）。
- **EFB（Exclusive Feature Bundling，互斥特征捆绑）**
  把"几乎不会同时取非零值"的稀疏特征（互斥特征）**捆绑成一个特征**。
  例如 one-hot 之后的几千维稀疏特征，可以压成几十维，显著减少参与分裂点搜索的特征数量。
  设置方式：`enable_bundle=True`（默认开启）。

### 6.3 Leaf-wise（叶子优先生长）vs Level-wise（按层生长）

**Level-wise（XGBoost 默认、sklearn 的 GBDT 也是这种）：**

```
        ●               第 0 层：1 个节点
      /   \
     ●     ●            第 1 层：2 个节点
    / \   / \
   ●   ● ●   ●          第 2 层：4 个节点（不管这些节点是不是都值得分裂）
```

同一层的所有节点**一起分裂**，长完这一层再长下一层。树很"整齐"。
缺点是有些节点的分裂收益其实很小（甚至为负），做了**无用功**。

**Leaf-wise（LightGBM 默认）：**

```
        ●
      /   \
     ●     ●            ← 先挑当前所有叶子里 Gain 最大的那个去分裂
    / \
   ●   ●                ← 再从全部叶子里挑 Gain 最大的（可能还是同一支）
  /
 ●                      ← 树会明显偏深、偏"歪"
```

每一轮从**当前所有叶子**中挑出"分裂收益 $\mathrm{Gain}$ 最大"的那一个单独分裂，
不管它在第几层。**把分裂预算花在刀刃上。**

| 维度 | Level-wise | Leaf-wise |
|---|---|---|
| 分裂顺序 | 按层，同层一起分 | 按 Gain，谁大分谁 |
| 树形 | 整齐对称 | 偏斜、偏深 |
| 同样叶子数下的损失 | 较高 | **更低**（更充分） |
| 过拟合风险 | 较低 | **较高**（容易长得很深） |
| 并行友好度 | 好（同层节点可并行） | 差一些（叶子之间有依赖） |
| 代表 | XGBoost、sklearn GBDT | **LightGBM** |

> 所以：LightGBM 更像是**专门挑最有价值的地方继续往下长**，所以速度快，
> 但参数没调好时也**更容易过拟合**。

### 6.4 `num_leaves` 与 `max_depth` 的关系

一棵二叉树中，叶子数 $T$ 和深度 $d$ 满足：

$$
\boxed{\;T\le 2^{d}\;}
$$

| `max_depth` | 理论上最多叶子数 $2^d$ |
|---|---|
| 3 | 8 |
| 5 | 32 |
| 7 | 128 |
| 8 | 256 |
| 10 | 1024 |

反过来说，`num_leaves=31` 意味着"至少要 5 层才装得下"（$2^5=32\ge 31$）。

> ⚠️ **不要把 `num_leaves` 和 `max_depth` 同时卡死**：
> 如果你设 `max_depth=3`（最多 8 个叶子）又设 `num_leaves=31`，深度上限会**先把树掐死**，
> `num_leaves` 根本用不满，白白浪费了"分裂预算"，还可能让模型**欠拟合**。

**官方建议：**

- `num_leaves` 是控制复杂度的**主参数**（默认 31，常用 31~255）；
- `max_depth` 只做**安全网**（设 `-1` 不限制，或设 7~10 防止树过分偏斜）。

**实践口诀：**

> 小数据（几千行）→ `num_leaves` 15~31，`min_child_samples` 30~100；
> 大数据（几十万行以上）→ 才敢把 `num_leaves` 调到 255 甚至 1023。

### 6.5 分裂收益 Gain 的直观含义

LightGBM 每训练一棵新树，本质是**选一个最好的位置长出新叶子**。怎么判断"好"？它算一个**分裂收益 Gain**：

> **Gain = 分开左右两边后的"纯度提升" − 分裂一次的手续费**

用二阶公式写出来，和 XGBoost 完全一致：

$$
\mathrm{Gain}=\frac{1}{2}\left[
\frac{G_L^{2}}{H_L+\lambda}+\frac{G_R^{2}}{H_R+\lambda}
-\frac{(G_L+G_R)^{2}}{H_L+H_R+\lambda}
\right]-\gamma
$$

- **$\mathrm{Gain}>0$ 才值得分**，越大说明这个分裂点越划算。
- LightGBM 会把所有候选位置打分一遍，**谁的 $\mathrm{Gain}$ 最大就先分谁** ——
  这就是"叶子优先生长"的本质。

> 不需要纠结 Gain 怎么算出来的，知道它干一件事就行：
> **打分 —— 哪个分裂点最划算就选哪个。**

**四种"值得分"与"不值得分"的直觉：**

| 情况 | $G$（梯度）特点 | Gain 直觉 |
|---|---|---|
| 左右两组样本的标签明显不同 | $G_L$ 与 $G_R$ 符号相反、各自绝对值大 | 纯度高，Gain 大 → **值得分** |
| 左右两组样本混得很均匀 | $G_L\approx G_R$ | 分了等于没分，Gain ≈ 0 → 不值得分 |
| 某一侧只有 1~2 个样本 | $G$ 由极少数样本决定 | 不稳定，靠 `min_child_samples` 挡掉 |
| 树已经很复杂 | —— | 被 $\gamma T$ 和 $\lambda\sum w_j^2$ 罚掉 → 不再分 |

### 6.6 LightGBM 的关键参数（`LGBMClassifier`）

| 参数 | 默认值 | 作用与调参方向 |
|---|---|---|
| `n_estimators` | `100` | 树的数量（轮数），有早停时是"上限" |
| `learning_rate` | `0.1` | 学习率 $\eta$，与 `n_estimators` 联动 |
| `num_leaves` | `31` | **主复杂度参数**：一棵树最多多少叶子，常用 31~255 |
| `max_depth` | `-1` | 只当安全网用（7~10）；与 `num_leaves` 满足 $T\le 2^d$ |
| `min_child_samples` | `20` | 叶子最少样本数，**最常用的抗过拟合参数**，噪声大就调大到 30~100 |
| `subsample` | `1.0` | 行采样（别名 `bagging_fraction`），需配 `subsample_freq=1` 才稳定生效 |
| `colsample_bytree` | `1.0` | 列采样（别名 `feature_fraction`），常用 0.7~0.9 |
| `reg_lambda` | `0.0` | L2 正则（别名 `lambda_l2`），压制叶子权重 |
| `reg_alpha` | `0.0` | L1 正则（别名 `lambda_l1`），可让权重变 0（稀疏化） |
| `min_split_gain` | `0.0` | 分裂所需最小 Gain（别名 `min_gain_to_split`），等价于 XGBoost 的 `gamma` |
| `max_bin` | `255` | 直方图桶数。调小 → 更快更省内存；调大 → 精度略高 |
| `verbose` | `1` | **设 `-1` 完全关闭 C 层日志**（否则会刷屏） |
| `n_jobs` | 自动 | 线程数，`-1` 用满；设 1 便于完全复现 |
| `boosting_type` | `'gbdt'` | 可选 `'dart'`（带 dropout）、`'goss'`（单边梯度采样，须 `subsample=1`） |
| `importance_type` | `'split'` | ⚠️ 特征重要性口径：`'split'` 数分裂次数，`'gain'` 数增益。**和 XGBoost/sklearn 的 gain 口径对齐才能横比** |

### 6.7 lightgbm 4.7.0 sklearn 接口的注意事项

```python
import lightgbm as lgb
from lightgbm import LGBMClassifier

model = LGBMClassifier(
    n_estimators=1000, learning_rate=0.05, num_leaves=31,
    subsample=0.8, subsample_freq=1, colsample_bytree=0.8,
    random_state=42, n_jobs=2, verbose=-1,        # verbose=-1 关日志
)

model.fit(
    X_train, y_train,
    eval_X=(X_val,), eval_y=(y_val,),             # ← 4.7.0 新写法（eval_set 已过时）
    eval_names=["验证集"],                          # ← 这个名字会成为 evals_result_ 的键
    eval_metric="binary_logloss",
    callbacks=[
        lgb.early_stopping(stopping_rounds=20, verbose=False),  # 早停且不打印
        lgb.log_evaluation(period=0),                           # 双保险：不打印训练日志
    ],
)

model.best_iteration_                 # 最优迭代轮数（= 实际用了多少轮）
model.evals_result_["验证集"]["binary_logloss"]   # 验证集损失曲线
```

**四个坑：**

1. ⚠️ **`eval_set` 在 lightgbm 4.7.0 已被标记为过时**（`LGBMDeprecationWarning`），
   新写法是 `eval_X=(X_val,), eval_y=(y_val,)`。
   课案里的 `model.fit(X_train, y_train)` 是旧版最简写法，不影响，但要做早停就得用新接口。
2. ✅ **`verbose=-1` 是关日志的关键**。否则会出现一大堆
   `[LightGBM] [Warning] No further splits with positive gain` 和 `[LightGBM] [Info] ...` 刷屏。
   > 顺便说明：`No further splits with positive gain` **不是报错**，
   > 它只是在说"当前这个叶子已经找不到 Gain > 0 的分裂点了"，是正常现象。
3. ✅ 如果关掉 `verbose=-1` 后仍有日志从回调里冒出来，
   补一个 `lgb.log_evaluation(period=0)`（period=0 表示"每 0 轮打印一次"，即不打印）。
4. ✅ **不要动私有 API**，例如 `lightgbm.basic._log_warning`。

**sklearn 接口 vs 原生接口的调用差异：**

```python
# ---------- sklearn 包装器接口（本目录 4 个脚本都用这种）----------
from lightgbm import LGBMClassifier
model = LGBMClassifier(n_estimators=100, learning_rate=0.1, num_leaves=31, verbose=-1)
model.fit(X_train, y_train)
model.predict(X_test); model.predict_proba(X_test)
# 优点：参数用 sklearn 风格；可直接进 Pipeline / GridSearchCV / cross_val_score

# ---------- 原生接口 ----------
import lightgbm as lgb
dtrain = lgb.Dataset(X_train, label=y_train)
params = {"objective": "binary", "learning_rate": 0.1, "num_leaves": 31, "verbose": -1}
booster = lgb.train(params, dtrain, num_boost_round=100)
# 优点：功能最全（自定义目标函数、lgb.cv 交叉验证、增量训练、直接保存模型）
```

> 两者底层是**同一个 Booster**，模型效果不会有本质差别，区别只在参数命名和功能覆盖。
> 类似的，XGBoost 的原生接口是 `xgb.DMatrix` + `xgb.train(params, dtrain, num_boost_round)`，
> 参数名用 `eta`、`max_depth`、`objective`、`eval_metric`。

## 七、GBDT / XGBoost / LightGBM 全面对比

### 7.1 核心特点与工程属性

| 对比维度 | GBDT（sklearn） | XGBoost | LightGBM |
|---|---|---|---|
| **全称** | Gradient Boosting Decision Tree | eXtreme Gradient Boosting | Light Gradient Boosting Machine |
| **核心特点** | 用后一棵树修正前一棵树的负梯度/残差 | 目标函数 + **显式正则化** + **二阶信息** + 工程加速 | **直方图算法** + **Leaf-wise 生长** + GOSS/EFB |
| **树生长方式** | Level-wise | Level-wise（默认） | **Leaf-wise** |
| **分裂点搜索** | 精确贪心枚举每个取值 | `exact`（精确）/ `approx`（加权分位数）/ `hist`（直方图） | 直方图分桶（`max_bin=255`） |
| **损失近似** | 一阶（负梯度） | **二阶泰勒展开** | **二阶泰勒展开** |
| **正则化** | ❌ 无显式正则项，只能靠 `max_depth`/`min_samples_leaf`/`subsample` | ✅ $\Omega(f)=\gamma T+\frac12\lambda\sum w_j^2$，还有 L1、列采样、行采样 | ✅ 同 XGBoost（`reg_lambda`/`reg_alpha`/`min_split_gain`） |
| **训练速度** | 慢（纯 Python + 精确贪心） | 快（C++ + 并行 + 直方图） | **最快**（直方图 + Leaf-wise + GOSS/EFB） |
| **相对速度（本目录 04 脚本实测，2 万行）** | 1.00×（基准 8.36 秒） | **52.6×**（0.159 秒） | **93.7×**（0.089 秒） |
| **内存占用** | 高 | 中（预排序块结构较占内存） | **低**（只存桶编号 + 梯度直方图） |
| **缺失值处理** | ❌ 不支持 NaN，需先填充 | ✅ 自动学习默认方向 | ✅ 自动处理（`use_missing=True`） |
| **类别特征** | ❌ 需 one-hot / 序数编码 | ⚠️ 需手动编码（`enable_categorical` 可支持） | ✅ 支持 `categorical_feature`，或直接喂 pandas category |
| **抗过拟合能力** | 弱（无正则） | **强**（正则项 + 列采样 + 行采样 + 剪枝） | 中（正则强，但 Leaf-wise 天生更激进，小数据上更容易过拟合） |
| **小数据表现** | 稳 | **稳**（推荐） | 需小心调 `num_leaves`，否则容易过拟合 |
| **大数据表现** | 差 | 好 | **最好** |
| **调参难点** | 参数少，难点是"没有正则旋钮" | 参数多但彼此正交性好，**调参最直观** | `num_leaves` 与 `max_depth`、`min_child_samples` 相互牵制，**最容易调出过拟合** |
| **默认参数可靠度** | 一般 | **最高**（开箱即用就不错） | 中（默认 `num_leaves=31` 在小数据上偏大） |
| **早停写法** | `validation_fraction` + `n_iter_no_change` + `tol` | 构造函数 `early_stopping_rounds` + `fit(eval_set=...)` | `callbacks=[lgb.early_stopping(...)]` + `fit(eval_X=..., eval_y=...)` |
| **sklearn 接口** | `sklearn.ensemble.GradientBoostingClassifier` | `xgboost.XGBClassifier` | `lightgbm.LGBMClassifier` |
| **原生接口** | 无 | `xgb.DMatrix` + `xgb.train` | `lgb.Dataset` + `lgb.train` / `lgb.cv` |
| **参数命名风格** | sklearn 风格 | `eta`、`num_boost_round`、`objective` | `num_leaves`、`bagging_fraction`、`feature_fraction`、`lambda_l2` |
| **适用场景** | 教学 / 快速原型 / 中小规模 | 通用比赛与生产 / 追求稳定与可解释调参 | 大规模数据 / 单机内存有限 / 高维稀疏特征 |

| 概念 | sklearn GBDT | XGBoost | LightGBM |

### 7.3 实测对比（本目录 `04_三种Boosting对比.py`）

**实验设置**：`make_classification(n_samples=1000, n_features=20, n_informative=10, random_state=42)`，
`train_test_split(test_size=0.3, random_state=42, stratify=y)`，
统一参数 `n_estimators=100, learning_rate=0.1, max_depth=3`。

> 下表中**准确率 / AUC / log loss / 最优轮数是确定性的**（随机种子固定，每次运行都相同）；
> **训练耗时是实测值，会随机器负载波动**，只用来比较数量级。

| 模型 | 准确率 | 训练耗时(秒，实测) | AUC | log loss | 早停最优轮数 |
|---|---|---|---|---|---|
| GBDT(sklearn) | 0.9233 | 0.29 | 0.9694 | 0.2291 | 137 |
| XGBoost | 0.9133 | 0.15 | 0.9634 | 0.2474 | 1081 |
| LightGBM | 0.9067 | 0.02 | 0.9631 | 0.2491 | 1191 |

**20000 条样本时的速度对比（同一参数）：**

| 模型 | 训练耗时(秒，实测) | 测试准确率 | 加速比 |
|---|---|---|---|
| GBDT(sklearn) | 7.79 | 0.9333 | 1.00× |
| XGBoost | 0.154 | 0.9320 | 50.58× |
| LightGBM | 0.097 | 0.9285 | **80.13×** |

**结论：**

1. **小数据（1000 行）上三者准确率差距只有 1~2 个百分点**，属于同一水平 ——
   它们共享同一个 Boosting 骨架，参数还统一了，差异主要来自正则化程度和生长策略。
2. **数据量放大 20 倍后，LightGBM / XGBoost 的速度优势才真正显现**（50~90 倍）。
   1000 行时耗时里框架启动开销占比不低，速度数字会随环境波动。
3. **早停轮数差 8 倍（137 vs 1081/1191）不是算法优劣**，而是三个因素叠加：
   列采样（XGB/LGB 有 `colsample_bytree=0.8`，GBDT 没有）、
   叶子权重收缩（XGB/LGB 的 $w_j^*=-G_j/(H_j+\lambda)$ 被 $\lambda$ 压小，GBDT 直接把树输出乘 $\eta$）、
   以及三者用的**验证集不是同一个**（GBDT 内部切 `validation_fraction=0.1`，XGB/LGB 用同一个 `X_val2`）。

## 八、超参数怎么调（三种算法分别小结）

### 8.0 通用调参原则（三者都适用）

```
第 1 步：定"学多久"
    learning_rate 先取 0.05~0.1，n_estimators 设一个大值 + 开启早停
    → 让早停告诉你到底需要多少棵树
    ★ 联动铁律：learning_rate 减半 → n_estimators 大约翻倍

第 2 步：定"单棵树多复杂"（影响最大，第一优先级）
    GBDT / XGBoost  → max_depth
    LightGBM        → num_leaves（主）+ max_depth（安全网）

第 3 步：加随机性压过拟合（性价比最高）
    行采样 subsample / bagging_fraction = 0.7~0.9
    列采样 colsample_bytree / feature_fraction / max_features = 0.7~0.9

第 4 步：正则化微调
    reg_lambda（L2）、reg_alpha（L1）、gamma / min_split_gain、min_child_samples

第 5 步：如果还想要最后一点点精度
    learning_rate 再减半 + n_estimators 翻倍（但训练时间线性增长）

第 6 步：评估一定要交叉验证 + 多指标（准确率 / AUC / log loss），
        不要只看一次划分 —— 1000 条样本上的单次评估有 ±1~2% 的抖动
```

### 8.1 GBDT（`GradientBoostingClassifier`）

| 参数 | 起点 | 调参方向 | 说明 |
|---|---|---|---|
| `learning_rate` | 0.1 | 0.05 ~ 0.1 | 越小越稳，需要更多树 |
| `n_estimators` | 早停 | 由 `n_iter_no_change` 定 | **不要手填固定值** |
| `max_depth` | 3 | 3 ~ 8 | **最有效的复杂度旋钮**，训练/测试差距大就先调小 |
| `min_samples_leaf` | 1 | 5 ~ 50 | 样本量不大时设大，避免不稳定的小叶子 |
| `subsample` | 1.0 | 0.7 ~ 0.9 | 随机梯度提升，提速 + 降方差 |
| `max_features` | `None` | `'sqrt'` / 0.5 ~ 0.8 | 高维稀疏数据上更有效 |
| `validation_fraction` | 0.1 | 0.1 ~ 0.2 | 训练集够大时才有意义 |
| `n_iter_no_change` | `None` | **20** | 早停耐心值，强烈建议开启 |
| `tol` | 1e-4 | 1e-4 | 早停阈值 |

**GBDT 的特殊难点**：它**没有正则化参数**。发现过拟合时，你只有
`max_depth` ↓、`min_samples_leaf` ↑、`learning_rate` ↓ 三个选择。
这往往就是"为什么该换 XGBoost/LightGBM"的直接原因。

### 8.2 XGBoost（`XGBClassifier`）

| 参数 | 起点 | 调参方向 | 说明 |
|---|---|---|---|
| `learning_rate` | 0.05 ~ 0.1 | 0.01 ~ 0.3 | 与 `n_estimators` 联动 |
| `n_estimators` | 早停（上限 1000+） | 由 `early_stopping_rounds` 定 | 写在构造函数里 |
| `max_depth` | 3 ~ 4 | 3 ~ 8 | 第一优先级的复杂度旋钮 |
| `min_child_weight` | 1 | 5 ~ 50 | 噪声大 / 样本少时调大（相当于 `min_samples_leaf`） |
| `gamma` | 0 | 0.1 / 1 / 5 | **剪枝手续费**。发现"树很多、叶子很碎"就加它；太大会欠拟合 |
| `subsample` | 1.0 | 0.7 ~ 0.9 | 行采样 |
| `colsample_bytree` | 1.0 | 0.7 ~ 0.9（高维 0.5） | 列采样，性价比最高的抗过拟合参数 |
| `reg_lambda` | 1.0 | 1 / 5 / 20 | L2，直接压小叶子权重 $w_j^*=-G_j/(H_j+\lambda)$ |
| `reg_alpha` | 0.0 | 0.1 ~ 1 | L1，特征很多、想自动稀疏化时用 |
| `eval_metric` | 按目标自动 | `'logloss'` / `'auc'` / `'error'` | 决定 `best_score` 的含义 |
| `early_stopping_rounds` | **20 ~ 50** | —— | 写在构造函数；`fit` 里配 `eval_set` |
| `tree_method` | `'hist'` | `'hist'` / `'exact'` / `'auto'` | `hist` 快且省内存，是默认推荐 |
| `verbosity` | 0 | —— | 静默日志 |

**调参顺序**：`learning_rate` + 早停 → `max_depth` / `min_child_weight` →
`subsample` / `colsample_bytree` → `gamma` / `reg_lambda`。
每次只动一个参数，都看验证集指标。

### 8.3 LightGBM（`LGBMClassifier`）

| 参数 | 起点 | 调参方向 | 说明 |
|---|---|---|---|
| `learning_rate` | 0.05 ~ 0.1 | 0.01 ~ 0.3 | 与 `n_estimators` 联动 |
| `n_estimators` | 早停（上限 1000+） | 由回调定 | —— |
| `num_leaves` | 31 | **15 ~ 255** | **主复杂度参数**。小数据 15~31，大数据才敢调大 |
| `max_depth` | -1 | 7 ~ 10（**仅安全网**） | 与 `num_leaves` 满足 $T\le 2^d$，**不要同时卡死** |
| `min_child_samples` | 20 | **30 ~ 100** | **最常用的抗过拟合参数**，小数据/噪声大时必调大 |
| `subsample` | 1.0 | 0.7 ~ 0.9（配 `subsample_freq=1`） | 行采样 |
| `colsample_bytree` | 1.0 | 0.7 ~ 0.9 | 列采样 |
| `reg_lambda` | 0.0 | 1 ~ 20 | L2 |
| `reg_alpha` | 0.0 | 0.1 ~ 1 | L1 |
| `min_split_gain` | 0.0 | 0.1 ~ 1 | 等价于 XGBoost 的 `gamma` |
| `max_bin` | 255 | 63 / 127 / 255 / 511 | 追求速度调小，追求精度调大 |
| `verbose` | 1 → **-1** | —— | **必开 `-1`**，否则日志刷屏 |
| `n_jobs` | 自动 | -1 用满 / 1 便于复现 | —— |
| `boosting_type` | `'gbdt'` | `'gbdt'` / `'dart'` / `'goss'` | `goss` 用于大数据提速（此时 `subsample=1`） |
| `importance_type` | `'split'` | 需要和 XGBoost 横比时设 `'gain'` | 口径不同，量纲完全不同 |

**LightGBM 的特殊难点**：Leaf-wise 天生更激进。
如果在小数据上 LightGBM 打不过 XGBoost，**八成是 `num_leaves` 太大 / `min_child_samples` 太小**，
先把这两个往保守方向调。

### 8.4 怎么选？（决策速查）

| 场景 | 建议 |
|---|---|
| 教学 / 快速原型 / 不想装第三方库 | **sklearn GBDT**：零额外依赖，`staged_predict` 还能直接画提升过程曲线 |
| 通用比赛与生产、想要稳定的默认表现 | **XGBoost**：默认参数最可靠，正则化最完整，缺失值自动处理，跨平台成熟 |
| 大规模数据（几万行以上）、内存有限 | **LightGBM**：直方图 + Leaf-wise，实测 2 万行时比 sklearn GBDT 快 90 倍 |
| 高维稀疏特征 | **LightGBM**（EFB 互斥特征捆绑）；或 XGBoost + 调小 `colsample_bytree` |
| 小数据且怕过拟合 | **XGBoost** 或 sklearn GBDT；若用 LightGBM 必须先调小 `num_leaves`、调大 `min_child_samples` |
| 类别特征多 | **LightGBM**（`categorical_feature` 直接吃类别，不用 one-hot） |
| 需要精确概率 | 三者都要做概率校准（`CalibratedClassifierCV`）——Boosting 的概率偏低置信 |

## 九、常见坑与学习建议

### 9.1 代码层面的坑（本机实测踩过的）

| 坑 | 现象 | 解决 |
|---|---|---|
| xgboost 3.x 手写 `objective` + `num_class` | 与 sklearn 接口冲突或产生告警 | **删掉这两个参数**，sklearn 包装器自动推断 |
| xgboost 3.x 把 `early_stopping_rounds` 传给 `fit()` | 报错 / 告警 | 写在**构造函数**里，`fit(eval_set=[(X_val, y_val)], verbose=False)` |
| xgboost 把 `best_iteration` 当树的数量 | 少算 1 棵树 | `best_iteration` **从 0 开始**，树数 = `best_iteration + 1` |
| lightgbm 4.7.0 用 `eval_set` | `LGBMDeprecationWarning` | 改用 `eval_X=(X_val,), eval_y=(y_val,)`（可用 `eval_names` 命名） |
| lightgbm 日志刷屏 | 大量 `[LightGBM] [Info]/[Warning]` | **`verbose=-1`**；再加 `callbacks=[lgb.log_evaluation(period=0)]` 双保险 |
| lightgbm 特征重要性量纲不对 | 数值是 70、67 这种整数 | 默认 `importance_type='split'`（分裂次数），要和 XGBoost 比就设 `'gain'` |
| `num_leaves` 和 `max_depth` 同时卡死 | `num_leaves=31` + `max_depth=3` 时树被掐死 | 记住 $T\le 2^d$，`max_depth` 只做安全网 |
| 树模型还去做标准化 | 白费功夫（没坏处但没用） | 树只比较特征顺序，**不需要标准化**；但类别特征要先编码 |
| `GradientBoostingClassifier` 找正则化参数 | 找不到 `reg_lambda`/`gamma` | **它确实没有**，只能靠 `max_depth`/`min_samples_leaf`/`subsample` |

### 9.2 方法论层面的坑

1. **不要用训练集指标判断模型好坏**。
   我们的 `03_LightGBM.py` 里，`num_leaves` 从 7 加到 255，训练集准确率全是 1.0000，
   但测试集 AUC 一路从 0.9760 掉到 0.9703 —— 光看训练集你永远发现不了过拟合。

2. **Boosting 的树不是越多越好**。
   `01_GBDT.py` 的曲线显示：训练损失从 1.3042 单调降到 0.0626，看起来"越来越好"；
   但测试损失在第 204 轮见底（0.3355）后回升到 0.3532。
   **能早停就早停**：更少的树 = 更小的模型 + 更快的预测 + 更低的过拟合风险。

3. **公平对比的三要素**：同一份数据、同一次划分、同一个评估指标。
   我们的 `04_三种Boosting对比.py` 严格遵守了这一点（连 `random_state` 都统一）。

4. **单次划分的评估不可信**。1000 条样本上测试集只有 300 条，
   准确率 ±1~2% 的波动完全正常。严谨结论要做交叉验证。

5. **特征重要性 ≠ 因果重要性**。
   它只反映"模型怎么用这个特征"，不代表这个特征真的导致了好结果。
   而且三者口径不同（`split` vs `gain`），横比前要统一。

6. **Boosting 对噪声敏感**。
   如果数据标签有大量噪声，随机森林往往比 Boosting 更稳 ——
   因为 Boosting 会把噪声当作"还没学好的残差"反复拟合。

### 9.3 学习路径建议

```
第 1 步：读懂加法模型           → 本文第三章 + 01_GBDT.py ① ② 节
第 2 步：手推一遍 GBDT 残差       → 考试提分例子 + 01_GBDT.py 的提升过程曲线
第 3 步：理解二阶展开与 Gain 公式  → 本文第五章 + 02_XGBoost.py 的 gamma 剪枝实验
第 4 步：理解直方图与 Leaf-wise    → 本文第六章 + 03_LightGBM.py 的 num_leaves/max_bin 实验
第 5 步：建立"参数—效果"直觉      → 04_三种Boosting对比.py，改参数、重跑、看数字变化
第 6 步：迁移到真实任务           → 换数据集、加交叉验证、做特征工程
```

> **记住一条主线**：三个算法共享同一个加法模型骨架
> $F_m(x)=F_{m-1}(x)+\eta f_m(x)$，
> 差别只在 (a) 每棵树"怎么长"、(b) 分裂点"怎么找"、(c) 目标函数"加了什么约束"。
> 掌握了这条主线，所有参数都能自己推导出它的作用。
