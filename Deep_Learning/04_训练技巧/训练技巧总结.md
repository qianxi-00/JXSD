## 0. 为什么"先看 loss 曲线形状"是最快的诊断手段

模型的参数有几十万、几百万个，但**训练健康与否只有两个数字能立刻告诉你：训练 loss 和验证 loss**。
把这两条曲线画出来，等于把高维参数空间里的问题投影到一张二维图上——大多数训练故障在图上都有固定的"形状签名"：

| 曲线签名 | 直接指向的问题 |
|---|---|
| 两条都高、都平 | 欠拟合（容量不足/训练不足） |
| 训练降、验证先降后**反弹** | 过拟合 |
| 两条剧烈上下跳 | 学习率过大 or batch 太小 |
| 两条都极慢下降 | 学习率过小 or 模型太大/精度太高 |
| 突然 NaN / 断线 | 梯度爆炸（也可能学习率爆炸） |
| 几乎不降 + 浅层梯度接近 0 | 梯度消失 |

**先看形状，再动手调参**，可以避免最常见的浪费：明明是欠拟合却去加 Dropout，明明是学习率太大却去加数据。

### 一条"好的" loss 曲线应该长什么样

1. **开头**：前几个 epoch 快速下降（模型在学最粗的规律）；
2. **中段**：下降变缓，呈平滑的幂律/指数尾巴（在精细拟合）；
3. **验证 loss**：始终紧贴训练 loss 上方一个**稳定的小间距**（泛化差距小），最后与训练 loss 一起走平；
4. **没有**尖刺、没有断点、没有"训练还在降而验证已经抬头"的剪刀口。

一旦出现 4 中任何一种异常，就按下文第五节的决策树排查。

## 1. 过拟合（Overfitting）

### 1.1 现象与曲线形态

- 训练 loss 持续下降，甚至可以降到接近 0（准确率 100%）；
- **验证 loss 先降后升**，形成一个 U 形（或 L 形后翘尾）；
- 训练结束时"验证 loss 比它的历史最低点高出一大截"。

用文字描述的形态（横轴 epoch，纵轴 loss）：

```
train ↓↓↓↓↓↓↓↓↓↓↓↓↓↓↓↓↓ (一路往下，贴近 0)
val   ↓↓↓↘______/↗↗↗↗↗   (先降 → 走平 → 反弹)
                ↑
          最佳早停点在这里
```

### 1.2 根本原因：Bias-Variance 权衡

把模型在某个样本上的期望误差拆开：

$$
\mathbb{E}\big[(y-\hat y)^2\big]
  = \underbrace{\big(\mathbb{E}[\hat y]-y_{\text{true}}\big)^2}_{\text{Bias}^2\ \text{偏差}}
  + \underbrace{\mathbb{E}\big[(\hat y-\mathbb{E}[\hat y])^2\big]}_{\text{Variance}\ \text{方差}}
  + \underbrace{\sigma^2_{\text{noise}}}_{\text{不可约噪声}}
$$

- **欠拟合 = 高偏差**：模型族根本装不下真实函数，$\mathbb{E}[\hat y]$ 就偏离 $y_{\text{true}}$；
- **过拟合 = 高方差**：模型族太大，换个训练集 $\hat y$ 就剧烈变化，把训练集里的**噪声**也拟合了进去。

过拟合的判据是"模型容量 > 数据有效信息量"：

$$
\text{可记忆的参数量} \;\gg\; \frac{\text{样本数}}{\text{每个样本的有效信息量}}
$$

当参数量远大于样本数时，模型总能用一组权重让**训练误差恰好为 0**（插值解），
而这组权重完全可能把每个噪声点都当成真的规律。注意 $\sigma^2_{\text{noise}}$ 那一项是**不可约**的：
数据本身带噪声时，训练 loss 降到 0 不是"学得好"，而是"学错了"。

### 1.3 诊断步骤

1. 画 train/val loss 双曲线 → 是否出现"剪刀口"（验证抬头）？
2. 算**泛化差距** `gap = val_loss − train_loss`（用同一把尺子，都在 `model.eval()` 下测）；
3. 记录 `argmin(val_loss)` 与最后一个 epoch 的 val_loss，两者差多少；
4. **检查验证集是否太小**：验证集只有几十条时，loss/accuracy 的统计涨落极大，
   必须另留一个更大的独立测试集来确认（本目录脚本用 48 条验证 + 400 条测试做对照）。

### 1.4 解决办法（按优先级）

| 优先级 | 手段 | 一句话原理 | 代价 |
|---|---|---|---|
| 1 | **加正则化**：Dropout、Weight Decay | 直接限制模型的有效容量 | 需要调强度 |
| 2 | **早停**（+最佳权重恢复） | 在 val_loss 最低点收手，零成本 | 需要校验集 |
| 3 | **数据增强** | 让"记住训练集"这件事变得没用 | 需要设计对的不变性 |
| 4 | **减小模型**（砍层/减宽） | 从源头降低容量 | 可能转为欠拟合 |
| 5 | **加数据 / 特征选择降维** | 提高数据信噪比，最根本 | 成本最高 |

Weight Decay 的公式（L2 正则）：在 loss 上加 $\frac{\lambda}{2}\|W\|^2$，梯度里多一项 $\lambda W$，
每步都把权重往 0 拉一点，抑制"大权重 + 尖锐边界"的解：

$$
L_{\text{total}} = L_{\text{CE}} + \frac{\lambda}{2}\|W\|^2,
\qquad
\nabla_W L_{\text{total}} = \nabla_W L_{\text{CE}} + \lambda W
$$

Dropout 的原理：训练时以概率 $p$ 随机把神经元置 0，等价于每步训练一个随机子网络，
最终近似于对指数多个子网络做**集成（ensemble）**；推理时用完整网络。它抑制了
"某个神经元专门记住某个样本"的协同适应（co-adaptation）。

### 1.5 本目录脚本的实测证据

数据：`make_moons(240, noise=0.35)`，train 192 / val 48，另留 400 条同分布独立测试集；
优化器 Adam(lr=1e-2)、batch 32、150 epoch（同一份数据、同样轮数，只改容量与正则）。

| 配置 | 参数量 | train_loss | val_loss | test_loss(400条) | 泛化差距 | val_acc | test_acc |
|---|---|---|---|---|---|---|---|
| 小模型（纯线性） | 22 | 0.3779 | 0.4265 | 0.3394 | 0.0485 | 0.792 | 0.850 |
| **大模型** | 132,866 | **0.1463** | **1.7512** | **0.8907** | **1.6050** | 0.854 | 0.827 |
| 大模型 + Dropout(0.5) | 132,866 | 0.2564 | 0.4394 | 0.4686 | 0.1830 | 0.854 | 0.898 |
| 大模型 + WeightDecay(1e-3) | 132,866 | 0.1992 | 0.3974 | 0.3356 | 0.1982 | 0.854 | 0.870 |
| **大模型 + 两者** | 132,866 | 0.2632 | **0.3578** | **0.2849** | **0.0946** | 0.771 | 0.855 |

- **过拟合的铁证**：大模型 val_loss 在第 **41** 个 epoch 触底 **0.3388**，随后一路反弹到 **1.7512**
  （回升 **1.4124**）；train_loss 却只有 0.1463。
- **正则化的证据**：train_loss 比大模型**高了 0.1170**（被压得没法死记），
  但 val_loss 低了 **1.3934**，泛化差距从 **1.6050 收窄到 0.0946**。
- **只加 Dropout / 只加 Weight Decay** 都能单独改善（val_loss 0.4394 / 0.3974），两者叠加最好。
- **一个反直觉的观察**：大模型的 test_acc 只从 0.855 掉到 0.827，test_loss 却涨了三倍多。
  原因是它**错得更自信**（对少数点给出极端概率），交叉熵损失因此爆炸。
  → **只看 accuracy 会漏掉过拟合，必须看 loss。**
- **决策边界**（`04训练技巧_01_决策边界对比.png`）：小模型是一条直线（欠拟合），
  大模型的边界被噪声点掰出尖角和孤立碎块，正则后回到平滑的大形状。
- **早停的价值**：patience=20 时在第 30 个 epoch 停手，此时 val_loss 已经从最低点 0.3535 涨到 0.5725；
  `restore()` 回滚最佳权重后回到 0.3535，测试集 acc = 0.865（不早停跑满 150 则是 1.7512）。
- **数据增强（纯 torch 手写，无正则大模型，120 epoch）**：
  无增强 test_loss 0.4695 → 加"高斯噪声 + 随机缩放"后 **0.2984**（train_loss 反而从 0.1908 升到 0.2605），
  test_acc 0.8625 → **0.8925**；只加随机缩放 0.3939（有改善但弱）；
  **bootstrap 重采样反而变差**（test_loss 0.5144）——因为它每轮只有约 63% 的样本被抽到，
  在小数据上等于"看的数据更少 + 放大噪声点权重"。**增强不是万能药，必须匹配标签不变性。**
- **无用特征越多越容易过拟合**（`make_classification`，n=1000，n_informative=2）：

  | 特征设置 | 参数量 | train_loss | val_loss | 泛化差距 | val_acc |
  |---|---|---|---|---|---|
  | 20 维（2 有效 + 10 冗余 + 8 噪声） | 5,634 | 0.0611 | 0.7344 | 0.6732 | 0.825 |
  | 2 维（只有有效特征） | 4,482 | 0.3299 | 0.2847 | −0.0452 | **0.920** |

  两份数据的**有效信息量完全相同**，只是多了 18 个无用维度，泛化差距就从 −0.05 涨到 +0.67。
  → 特征选择 / 降维本身就是一种过拟合缓解手段。

## 2. 欠拟合（Underfitting）

### 2.1 现象与曲线形态

- 训练 loss 和验证 loss **都高**，而且**都不再下降**（两条曲线贴在一起走平在高位）；
- 训练集准确率本身就很低（例：二分类 0.82，说明连训练数据都没学好）。

```
train ─────────────── 高且平
val   ─────────────── 高且平（紧贴 train）
```

### 2.2 根本原因

高偏差，即模型族**不包含**（或很难优化到）真实函数：

$$
\inf_{f\in\mathcal{F}}\ \mathbb{E}\big[(y-f(x))^2\big] \ \text{本身就很大}
$$

三种常见来源：
1. **容量不足**：线性模型学非线性数据；层数/宽度太小；
2. **优化不足**：学习率太小走不动、epoch 太少、初始化太差导致梯度消失（见第 5 节）；
3. **数据/预处理有问题**：标签标错、归一化做错、特征本身不含信息。

### 2.3 诊断步骤

1. 看**训练** loss 是否够低——这是欠拟合与过拟合的分水岭（欠拟合连训练集都没拟合好）；
2. 用小批量数据做**过拟合测试**：故意拿 10 条样本训练，如果 loss 降不到接近 0，
   说明是"优化/容量"问题，而不是"数据太难"；
3. 检查学习率是否过小、是否所有参数都在更新（梯度范数是否为 0）；
4. 检查数据管线：标签对不对？标准化是不是在训练集上 fit 的？

### 2.4 解决办法（按优先级）

1. **增大模型**：加深、加宽（容量不够时，任何正则化都是帮倒忙）；
2. **调大学习率**：步长太小会在高处慢慢挪，看起来像"不降"；
3. **训练更久**：增加 epoch；
4. **降低正则化强度**：减小 Dropout 概率、减小 weight_decay；
5. **检查数据**：标签错误、归一化不对（脏数据会让模型永远学不会）。

### 2.5 本目录脚本的实测证据

同一份数据、Adam(lr=1e-2)、batch 32、120 epoch：

| 配置 | 参数量 | train_loss | test_loss | train_acc | test_acc |
|---|---|---|---|---|---|
| 小模型 + lr=1e-2（基准） | 22 | 0.3778 | 0.3397 | 0.8229 | 0.850 |
| **增大模型 + lr=1e-2** | 4,482 | **0.1976** | 0.3869 | **0.8906** | 0.860 |
| 增大模型 + lr=**1e-4**（太小） | 4,482 | 0.3479 | 0.3215 | 0.8385 | 0.865 |
| 小模型 + lr=1e-4（两个毛病都有） | 22 | 0.6043 | 0.5984 | 0.8281 | 0.853 |

- **增大模型**：参数量 22 → 4,482，train_loss 0.3778 → **0.1976**，train_acc 0.8229 → **0.8906**。
  欠拟合的定义就是"连训练集都没拟合好"，所以**先看训练侧指标**。
- **调大学习率**：同一个中等模型，lr 1e-4 → 1e-2，train_loss 0.3479 → 0.1976，train_acc 0.8385 → 0.8906。
  小 lr 不是"学得稳"，而是"走不动"。
- **一个必须记住的副作用**：中等模型的 train_loss 比小模型低得多，但 test_loss（0.3869）
  **反而比小模型（0.3397）差**——加容量解决欠拟合的同时开始引入过拟合。
  **容量不是越大越好：加容量通常要同时配上正则化/早停。**

## 3. 损失震荡（Loss Oscillation）

### 3.1 现象与曲线形态

- loss 曲线剧烈上下跳动，看不到平滑的下降趋势；极端时直接变成 NaN。
- 与"噪声引起的正常抖动"的区别：震荡的**振幅不随时间衰减**，甚至越来越大。

```
train ↗↘↗↘↗↘↗   (锯齿状，包络不收敛)
      ↘↗↘↗↘
```

### 3.2 根本原因（公式）

梯度下降更新：$\theta_{t+1} = \theta_t - \eta\nabla L(\theta_t)$。
在极小点附近把 loss 近似成二次型 $L(\theta)\approx\frac12 a\theta^2$（$a$ 是曲率/最大特征值），则

$$
\theta_{t+1} = (1-\eta a)\theta_t
\quad\Longrightarrow\quad
\text{收敛条件}\ |1-\eta a|<1 \iff \eta < \frac{2}{a}
$$

- $\eta < 2/a$：单调收敛；
- $\eta$ 略大于 $2/a$：每步**跨过**最优点弹到对面，误差被放大 → **震荡**；
- $\eta \gg 2/a$：误差按 $|1-\eta a|^t$ 指数增长 → 几步内就 inf/NaN（**发散**）。

加上动量后等效步长变成 $\eta/(1-\beta)$，所以带 momentum 时更容易炸。

另一个来源是 **batch 太小**：mini-batch 梯度是无偏但带噪的估计
$\hat g = g + \epsilon,\ \mathbb{E}[\epsilon]=0,\ \mathrm{Var}[\epsilon]\propto 1/B$，
噪声直接变成参数上的随机游走，曲线出现毛刺。

### 3.3 诊断步骤

1. 先看学习率——**90% 的震荡是学习率太大**；
2. 看振幅与 trend：振幅固定不降 → 学习率接近临界值；振幅指数增长 → 已经发散；
3. 打印梯度范数：如果梯度范数正常但曲线抖 → 是 batch 太小的噪声；
4. 检查数据是否有异常样本导致个别 batch 的 loss 尖峰。

### 3.4 解决办法（按优先级）

1. **降低学习率**（优先，通常一步解决；可以除以 3 或除以 10 试）；
2. **增大 batch size**（让梯度估计更准，但别大到梯度不准/显存不够）；
3. **梯度裁剪** `clip_grad_norm_(model.parameters(), max_norm=1.0)`（限制单步总长度）；
4. 加学习率预热 / 余弦退火等调度（见课案"学习率调度"一节）。

### 3.5 本目录脚本的实测证据

**学习率**（同一个 20 层大模型，纯 SGD + momentum=0.9、batch 32、150 epoch）：

| 学习率 | 末段 30 epoch 的 loss 标准差 | 相邻 epoch 平均变化 | 结果 |
|---|---|---|---|
| 1e-3 | 0.0021 | 0.00024 | 平稳下降 |
| 1e-1 | 0.0517 | 0.01744（**72.6 倍**） | 明显震荡，但仍能学 |
| 0.5 | 29.86 | 6.08770 | 第 **105** 个 epoch loss 变成 **NaN**（发散） |

`lr=0.5` 时脚本用 `torch.isfinite(loss)` 捕获并**优雅停止**（不打印异常栈）：
loss 先冲到 166.96，然后变 NaN —— 这就是"学习率过大"的极端形态。

**batch size**（纯 SGD、lr=0.05、60 epoch）：

| batch_size | 末段 40 epoch 的相邻变化 | 最终 train_loss | 说明 |
|---|---|---|---|
| 8 | 0.00644 | 0.2631 | 梯度噪声大，毛刺明显 |
| 128 | 0.00086 | 0.3455 | 梯度更准，曲线平滑 |

两者相差 **7.5 倍** —— 小 batch 的梯度噪声直接写在了曲线上。

## 4. 训练缓慢（Slow Training）

### 4.1 现象与曲线形态

- loss **在降，但极慢**：跑完所有 epoch 还离目标水平很远；
- 或者每个 epoch 耗时极长（计算瓶颈，而不是优化瓶颈）。

```
train ↘‾‾‾‾‾‾‾‾‾‾‾  (斜率接近 0，但确实在降)
      目标线 ----------  (跑满 epoch 也没碰到)
```

### 4.2 根本原因

1. **学习率太小**：$-\eta\nabla L$ 里 $\eta$ 是线性因子，$\eta$ 小 10 倍，同样步数走的距离就小 10 倍；
2. **模型/精度太大**：算力成为瓶颈（每 epoch 时间很长）；
3. 也可能是**病态曲率**（不同方向曲率差几个数量级 → 之字形慢收敛）、初始化太差、梯度接近消失。

### 4.3 诊断步骤

1. 先分清是"每 epoch 慢"还是"每 epoch 快但下降慢"——前者是算力问题，后者是优化问题；
2. 打印"达到某个 val_loss 阈值用了几个 epoch"，用数字量化"慢"；
3. 试跑 1 个 epoch 看耗时与 loss 下降幅度（快速迭代诊断）；
4. 检查学习率、batch size、以及梯度范数量级。

### 4.4 解决办法（按优先级）

1. **调大学习率**：让每一步走得更远（最直接）；
2. **减小模型**：剪枝、蒸馏、换更轻量的架构；
3. **混合精度训练**：`torch.cuda.amp`（需 GPU/Tensor Core）；
4. **增大 batch size**：充分利用 GPU 并行；
5. **降低数据精度**：float16 代替 float32（同样只在有硬件加速时有效）。

### 4.5 本目录脚本的实测证据

阈值取 `val_loss < 0.4450`（约等于最优曲线的最终水平），三个学习率各训 150 epoch：

| 学习率 | 150 epoch 后 val_loss | 达到阈值的 epoch | test_acc |
|---|---|---|---|
| 1e-5 | 0.6712（≈ 瞎猜的 ln2=0.693） | **从未达到** | 0.695 |
| 1e-3 | 0.4238 | 第 **28** 个 epoch | 0.858 |
| 1e-1 | 0.4753 | 第 **1** 个 epoch | 0.860 |

→ 小 lr 的巨大差距一目了然：**lr=1e-5 连 150 个 epoch 都到不了 lr=1e-1 一步的水平**。
但也要注意陷阱：lr=1e-1 冲得快，它的 val_loss 最后反而**回升**到 0.4753（很快转为过拟合）。
**学习率的选择是"快"与"稳"的折中。**

**float32 vs float16 前向耗时**（同一个大模型、同一输入，各 80 次前向取平均）：
实测 float32 ≈ **0.41 ms/次**，float16 ≈ **6.2 ms/次**，float16 反而慢 **约 15 倍**
（具体数值每次运行会浮动，但"float16 在 CPU 上更慢"这个结论稳定不变）。

原因：**CPU 没有 fp16 硬件加速单元**，PyTorch 只能把 fp16 转成 fp32 算、再转回来，
额外的类型转换开销超过了位宽减半带来的收益。所以"降低数据精度"这一招只对
有 Tensor Core 的 GPU 有效（显存减半 + 算力翻数倍）。
同一台机器上 `torch.autocast("cpu", dtype=torch.bfloat16)` 也直接抛 `RuntimeError`（CPU 不支持），
脚本用 `try/except` 兜住并打印说明——**混合精度训练在本机只能做文字讲解**。

## 5. 梯度爆炸与梯度消失

### 5.1 现象对照表（课案原文）

| | 训练 loss | 梯度值 | 参数更新 |
|---|---|---|---|
| 梯度爆炸 | 突然变成 NaN | 极大（可能几千、几万） | 一步跨太远，参数变成 NaN |
| 梯度消失 | 几乎不降，停在一个高值 | 极小（接近 0） | 参数几乎不动，训不起来 |

### 5.2 同一个根源：反向传播的连乘

$$
\frac{\partial L}{\partial W_1}
= \frac{\partial L}{\partial h_L}
  \prod_{k=2}^{L}\Big(\mathrm{diag}\big(\sigma'(z_k)\big)W_k\Big)
  \frac{\partial h_1}{\partial W_1}
$$

- 每个因子的尺度 $<1$ → 乘 $L$ 次后趋近 0 → **消失**；
- 每个因子的尺度 $>1$ → 乘 $L$ 次后指数增长 → **爆炸**。

增长上界（爆炸侧）：

$$
\Big\|\prod_{k}\mathrm{diag}(\sigma'(z_k))W_k\Big\|
\le \prod_k \|W_k\|\cdot\max|\sigma'|
= \big(s\|W\|\big)^{L}
$$

**Sigmoid 的宿命**：$\sigma'(x)=\sigma(x)(1-\sigma(x))\le 0.25$，
就算网络一直工作在最佳点（$x\approx0$），20 层也只有

$$
0.25^{20} \approx 9.1\times10^{-13}
$$

再叠加饱和区（$|x|>5$ 时 $\sigma'$ 掉到 $10^{-3}$ 以下、$|x|=10$ 时只有 $4.5\times10^{-5}$），
梯度很快就会下溢到 float32 精度之外。

### 5.3 本目录脚本的实测证据（20 层 × 64 宽，batch 32）

**（a）逐层梯度范数（默认初始化，从输出层往输入层看）**

| 激活函数 | 第 20 层 | 第 10 层 | 第 1 层 | 衰减数量级 |
|---|---|---|---|---|
| Sigmoid | 2.604e+02 | 8.698e−07 | **5.618e−15** | **16.7** |
| Tanh | 2.616e+01 | 1.292e−01 | 1.394e−03 | 4.3 |
| ReLU | 1.331e+01 | 1.099e−03 | 9.988e−07 | 7.1 |

**（b）初始化尺度（同一个 20 层网络）**

| 激活 + 初始化 | 第 20 层 | 第 1 层 | 结论 |
|---|---|---|---|
| Sigmoid + std=0.01 | 2.577e+02 | **0（下溢）** | 信号在浅层前就衰减没了，网络是死的 |
| Sigmoid + std=1.0 | 1.815e+02 | 3.280e+00 | 32.7% 单元落在 **饱和区**（$|z|>5$），有梯度但学不动 |
| ReLU + std=1.0 | inf | inf | 前向直接溢出，梯度全 NaN |
| ReLU + std=0.01 | 0（下溢） | 0（下溢） | 同样死掉 |
| **ReLU + kaiming_normal_** | 1.582e+03 | **2.097e+03** | 只差 **0.12 个数量级**（比值 1.33），20 层尺度不衰减 |

**（c）梯度爆炸**

- 温和版（tanh + std=1.5）：第 20 层 6.792e+01 → 第 1 层 **8.109e+08**，逐层指数增长 **7.1 个数量级**；
- 真爆炸（relu + std=1.0 且每层权重 ×3）：前向 loss 直接 = **inf**，
  `torch.isfinite(loss) = False`，反向传播后 **20/20 层**的梯度全含 NaN/inf；
  脚本检测到非有限值后打印说明并停止更新，**不抛任何异常栈**。

**（d）RNN：同一个矩阵在时间维连乘**

$$
\frac{\partial h_t}{\partial h_{t-k}}
= \prod_{i=0}^{k-1}\mathrm{diag}\big(\tanh'(z_{t-i})\big)\,W_{hh}
$$

实测 $\|\partial L/\partial h_0\|$ 随序列长度 $T$（loss 只取最后一个时间步）：

| $W_{hh}$ 缩放 | T=5 | T=20 | T=50 | 变化 |
|---|---|---|---|---|
| ×0.8（谱半径<1） | 1.350e−01 | 2.831e−07 | **1.612e−18** | 衰减 8.4e+16 倍（**消失**） |
| ×5.0（谱半径>1） | 2.971e+02 | 1.966e+04 | **2.785e+07** | 放大 9.4e+04 倍（**爆炸**） |

→ 这就是"RNN 学不会长期依赖"和"RNN 训练容易炸"的**同一个原因**：$\rho^k$。

**（e）梯度裁剪的数值验证**

裁剪公式（按范数，等比缩小、方向不变）：

$$
\|g\| = \sqrt{\sum_i \|g_i\|^2},
\qquad
g \leftarrow g\cdot\min\Big(1,\ \frac{\text{max\_norm}}{\|g\|}\Big)
$$

实测（在一个真爆炸的 RNN 梯度上）：

| 指标 | 裁剪前 | 裁剪后 |
|---|---|---|
| `total_norm` | 3.023e+07 | **1.000000**（恰好等于 max_norm） |
| 最大单元素 $\|g\|$ | 6.786e+06 | ≤ 1.0 |
| 方向余弦相似度 | — | **1.0000000000** |

→ 余弦相似度严格为 1 证明：**裁剪只缩小长度，完全不改方向**。

对照 `clip_grad_value_(clip_value=0.1)`：最大单元素从 6.786e+06 截到 0.1，
但方向余弦只有 **0.674826（≠1）**——**按值裁剪会改变梯度方向**（各分量被裁比例不同），
所以"按范数等比缩小"才是默认首选。

**（f）裁剪让训练稳定（同一个爆炸 RNN：`weight_hh_l0 × 2.5`，序列长度 30，40 epoch）**

| 配置 | 首轮 loss | 最低 loss | 末轮 loss | 首轮梯度总范数 | 饱和区比例 |
|---|---|---|---|---|---|
| 不裁剪 | 0.6904 | 0.5859 | **0.6805**（≈没学） | 1.171e+00 | **31.0%** |
| 裁剪 max_norm=1.0 | 0.6724 | 0.2254 | **0.3353** | 3.849e+00 | **3.7%** |

不裁剪组有 31% 的隐藏单元冲进了 tanh 饱和区（$|z|>3$，$\tanh'<0.01$），
此后"梯度有值但没方向"，loss 一直在 0.58~0.68 之间晃；裁剪组只有 3.7% 饱和，loss 稳步降到 0.3353。

### 5.4 五种解决方案（课案表格）+ 实测证据

| 方案 | 怎么解决 | 本目录实测证据 |
|---|---|---|
| **ReLU 替代 Sigmoid/Tanh** | ReLU 正半轴导数为 1，不压缩梯度 | Sigmoid 第 1 层 5.618e−15 → Tanh 1.394e−03 → ReLU 9.988e−07（默认初始化下） |
| **Kaiming / Xavier 初始化** | 让每层权重的方差刚好抵消，保持梯度尺度大致稳定 | ReLU + `kaiming_normal_`：第 20 层 1.582e+03 / 第 1 层 2.097e+03，**只差 0.12 个数量级**；而 std=0.01 时梯度直接下溢为 0 |
| **BatchNorm / LayerNorm** | 把每层输入稳定在激活函数的非饱和区，饱和区导数 $\sigma'$ 不会趋近 0 | Sigmoid 网每层加 `BatchNorm1d`：第 1 层梯度 **5.618e−15 → 5.911e+01（提升 16.0 个数量级）**；std=1.0 场景饱和比例 **32.7% → 0.0%** |
| **残差连接** | 旁路 $x+F(x)$ 求导得 $1+F'(x)$，给梯度加一条直传通道（LSTM 侧梯度消失时同理） | 默认初始化下第 1 层梯度：Sigmoid **5.618e−15 → 2.033e+03**（提升 17.6 个数量级）、Tanh 1.394e−03 → 8.094e+03（6.8）、ReLU 9.988e−07 → 3.882e+06（12.6） |
| **梯度裁剪** | 梯度总长度超标就等比缩小，防一步跨飞 | 见 5.3(e)(f) |

> **饱和区导数值**：以 Sigmoid 为例，当输入 $x$ 很大（例如 $x>5$）或很小（$x<-5$）时，
> 输出几乎贴在 0 或 1 上不变了——这就是**饱和**。饱和区导数值 $\sigma'(x)$ 接近 0，
> 反向传播时梯度会被压扁。BatchNorm / LayerNorm 把每层输入稳在 0 均值附近，
> 避免进入饱和区，导数维持在正常范围，梯度就不会消失。
> （数值参考：$\sigma'(0)=0.25$、$\sigma'(5)=6.5\times10^{-3}$、$\sigma'(10)=4.5\times10^{-5}$。）

**关于 BatchNorm 的诚实补充**：BN 解决的是**饱和**，不是"Sigmoid 导数上界只有 0.25"这件事。
20 层 Sigmoid + BN 的第 1 层梯度（5.911e+01）虽然比不加 BN 好了 16 个数量级，
但比 ReLU + Kaiming（2.097e+03）仍小很多。**标准答案是三件套一起上：ReLU + Kaiming + BN（+ 裁剪保险）。**

### 5.5 LSTM 的类比：把"必然消失"变成"模型可以选择"

LSTM 的细胞状态更新：

$$
C_t = f_t\odot C_{t-1} + i_t\odot\tilde C_t
$$

- 在普通 RNN 里 $h_t = \tanh(W_{hh}h_{t-1}+\dots)$，梯度要乘 $\prod \mathrm{diag}(\tanh')\,W_{hh}$——
  **矩阵连乘**，$\|W_{hh}\|^k$ 决定指数衰减还是爆炸；
- 在 LSTM 里 $C_{t-1}$ 是**加**上去的，所以

$$
\frac{\partial C_t}{\partial C_{t-1}} = \mathrm{diag}(f_t)
$$

  这是**对角矩阵**（逐元素相乘），不是矩阵连乘。当遗忘门 $f_t\approx1$ 时，
  梯度可以近似无损地穿过很多时间步。

> 课案原话：**"LSTM 把梯度消失从'必然'变成了'模型可以选择'"**——
> 该记的东西（$f_t\to1$）长期保留，该忘的东西（$f_t\to0$）主动清掉。

### 5.6 防梯度爆炸/消失的标准配置（课案代码，已实测跑通）

```python
def init_weights(m):
    if isinstance(m, nn.Linear):
        nn.init.kaiming_uniform_(m.weight)   # ReLU 用 Kaiming，控制 W 的尺度
        nn.init.zeros_(m.bias)

model = nn.Sequential(
    nn.Linear(256, 128), nn.BatchNorm1d(128), nn.ReLU(),
    nn.Linear(128, 64),  nn.BatchNorm1d(64),  nn.ReLU(),
    nn.Linear(64, 10),
)
model.apply(init_weights)

for batch in dataloader:
    optimizer.zero_grad()
    loss.backward()
    torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)  # 最后一道保险：防爆炸
    optimizer.step()
```

实测（`make_classification` 10 类、20 维、1000 条；`nn.Linear(20→256→128→64→10)`，48,074 参数，Adam lr=1e-2）：

- 训练 loss：**1.7745 → 0.0912**（20 个 epoch 降了一个多数量级），loss 稳定下降、没有 NaN；
- 每步"裁剪前"的梯度总范数只有 **0.46 ~ 1.44**，说明这套配置下梯度本来就健康，
  `clip_grad_norm_` 基本没被触发——它是**保险**，不是加速器；
- 验证 loss = 1.5727、验证准确率 = 0.675（明显高于训练 loss → 这个数据集上已经开始过拟合，
  属于第 1 节的问题，需要用正则化/早停/加数据解决）。

## 6. 诊断决策树

```
看到 loss 曲线异常
│
├─ loss 突然变成 NaN / inf，或曲线断掉
│   ├─ 打印梯度范数（loss.backward() 之后、step() 之前）
│   │   ├─ total_norm 异常大（1e3+）→ 梯度爆炸
│   │   │   ├─ 立刻加 torch.nn.utils.clip_grad_norm_(params, max_norm=1.0)   ← 第一优先
│   │   │   ├─ 学习率除以 3～10（含 momentum 时等效步长 = lr/(1-β)，更容易炸）
│   │   │   ├─ 换 Kaiming/Xavier 初始化，别用 std 过大的初始化
│   │   │   ├─ 深网加 BatchNorm / 残差；RNN 缩短序列或换 LSTM/GRU
│   │   │   └─ 检查输入特征尺度（未标准化的特征会放大梯度）
│   │   └─ total_norm 正常 → 是学习率本身太大（见"震荡"分支）或 loss 里有 log(0)/除零
│   └─ 用 torch.isfinite(loss) 做守卫：检测到非有限值就跳过这一步（绝不让 NaN 写进参数）
│
├─ val_loss 先降后反弹（训练 loss 还在降）→ 过拟合
│   ├─ 先确认验证集够大（几十条的验证集涨落极大，另留测试集复核）
│   ├─ 1) 加正则：Dropout(0.2~0.5)、weight_decay(1e-4~1e-2)
│   ├─ 2) 早停 + 最佳权重恢复（patience 5~20，看验证 loss 不再改善）
│   ├─ 3) 数据增强（必须匹配"标签不变性"，否则可能帮倒忙）
│   ├─ 4) 减小模型（砍层/减宽）
│   └─ 5) 加数据 / 特征选择降维
│
├─ loss 抖动剧烈、包络不收敛（或越来越大）→ 震荡
│   ├─ 降低学习率（优先，×0.3 或 ×0.1 试）            ← 90% 的情况这一步就够
│   ├─ 增大 batch size（噪声 ∝ 1/√B）
│   ├─ 加梯度裁剪
│   └─ 加 warmup / 余弦退火
│
├─ loss 下降极慢，且训练 loss 也高 → 欠拟合 or 训练缓慢
│   ├─ 先做过拟合测试：10 条样本能否把 train loss 打到 ~0？
│   │   ├─ 打不到 → 优化问题：调大学习率 / 换更好初始化 / 检查梯度是否为 0（梯度消失）
│   │   └─ 打得到 → 容量问题：加深加宽
│   ├─ 降低正则化强度（Dropout 概率、weight_decay）
│   ├─ 检查数据：标签错误？归一化用错了统计量？特征里有没有信息？
│   └─ 每 epoch 都很慢 → 是算力问题：减小模型 / 大 batch / 混合精度（需 GPU）
│
└─ loss 不降 + 浅层梯度接近 0 → 梯度消失
    ├─ Sigmoid/Tanh 换成 ReLU（导数不压缩）
    ├─ 换 Kaiming/Xavier 初始化（尺度匹配激活函数）
    ├─ 加 BatchNorm/LayerNorm（躲开饱和区）
    ├─ 加深网加残差连接；RNN 换 LSTM/GRU
    └─ 别把 Sigmoid 叠太深（20 层 Sigmoid 的理论上限只有 0.25^20 ≈ 9.1e-13）
```

## 9. 课案原文的关键结论（值得反复看）

- **诊断总纲**：*"训练中遇到问题时先看 loss 曲线的形状，它能直接告诉你问题出在哪。"*
- **过拟合**：模型容量 > 数据有效信息量；模型在"背"训练集答案，而不是学通用规律。
- **欠拟合**：训练 loss 和验证 loss 都高且不再下降，模型还没学会数据的规律。
- **震荡**：学习率太大，每次更新跨过最优点又弹回来；也可能是 batch size 太小。
- **缓慢**：学习率太小（步长不够）或模型太大（计算量过大）。
- **梯度爆炸/消失**：梯度值极大 → 一步跨太远参数变 NaN；梯度接近 0 → 参数几乎不动。
- **饱和区**：Sigmoid 输入 $|x|>5$ 后输出贴在 0/1 上不变，$\sigma'$ 接近 0；
  BatchNorm/LayerNorm 把输入稳在 0 均值附近，导数维持在正常范围。
- **残差连接**：旁路 $x+F(x)$ 求导得 $1+F'(x)$，等于给梯度加了一条直传通道；
  **LSTM 侧梯度消失时同理**——$C_t=f_t\odot C_{t-1}+i_t\odot\tilde C_t$ 里的 $f_t$ 就是那条免衰减旁路。
- **损失函数侧的两条结论**（课案"损失函数"一节）：
  - **KL 散度 = 交叉熵 − 信息熵**：$D_{KL}(p\|q)=H(p,q)-H(p)$。
    由于 $H(p)$ 与模型参数无关，**最小化交叉熵 ⟺ 最小化 KL 散度**，
    这就是为什么分类任务可以直接用交叉熵当损失。
  - **Adam = Momentum + RMSProp**：一阶动量 $m_t$（像 Momentum，抹平梯度方向）
    + 二阶动量 $v_t$（像 RMSProp，对不同参数给不同步长），
    再做偏差修正 $\hat m_t,\hat v_t$ 与 $\theta\leftarrow\theta-\eta\hat m_t/(\sqrt{\hat v_t}+\epsilon)$。
    Adam 收敛快、对学习率不敏感，但泛化有时不如调好的 SGD+Momentum。
- **LSTM 的意义**：**"把梯度消失从'必然'变成了'模型可以选择'"**。

## 10. 一页纸行动清单

1. **先画曲线**：每个 epoch 都记录 train/val 的 loss（和 accuracy），
   `train_loss` 一定要在 `model.eval()` 下测，否则和 `val_loss` 不是同一把尺子。
2. **算泛化差距**：`gap = val_loss − train_loss`，并记录 `argmin(val_loss)` 出现在第几个 epoch。
3. **看形状诊断**：剪刀口→过拟合；双高平→欠拟合；锯齿→学习率/ batch；蜗牛→学习率/算力；
   NaN→梯度爆炸（先裁剪）；不降+浅层梯度≈0→梯度消失。
4. **按优先级动手**：正则化 → 早停 → 增强/加数据 → 调模型；
   学习率类问题先动学习率；梯度类问题先上"ReLU + Kaiming + BN + 裁剪"组合拳。
5. **守住底线**：`torch.isfinite(loss)` 守卫 + `clip_grad_norm_(max_norm=1.0)`，
   任何实验都不要让 NaN 静默地污染参数。
6. **别用 accuracy 代替 loss**：过拟合的模型往往"错得更自信"，
   accuracy 只掉一点点，交叉熵损失却涨好几倍。
