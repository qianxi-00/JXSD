## 一、为什么需要配置管理

同一个程序，在**开发机**上连本地 SQLite，在**测试环境**连测试 MySQL，在**生产环境**连主库并在 HTTPS 后面跑。
这些"会随环境变化的值"就是**配置**。

**反例（硬编码）：**

```python
# 千万不要这样写
engine = create_engine("mysql+pymysql://root:Sidnasa25@localhost:3306/my_database")  # 密码写进代码
DEBUG = True   # 上线忘改
```

后果：改一个数据库地址要改代码、重新打包、重新发布；密码随代码进 Git 泄露；测试环境误连生产库。

**正解：配置与代码分离。** 代码只声明"我需要一个 database_url"，具体值由运行环境提供：

```
代码（不变）  +  配置（每个环境不同）  →  行为不同的同一个程序
```

## 二、Pydantic Settings 是什么

`pydantic-settings` 是 Pydantic 官方出的配置库，把配置声明成一个 **Pydantic 模型**：

```python
from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    app_name: str = "我的应用"
    database_url: str = "sqlite:///./app.db"
    async_database_url: str = "sqlite+aiosqlite:///./app.db"
    admin_email: str = "admin@example.com"
    jwt_secret: str = "your-super-secret-key-change-in-production"
    jwt_algorithm: str = "HS256"

    model_config = SettingsConfigDict(
        env_file=".env",              # 从 .env 文件读
        env_file_encoding="utf-8",    # 中文乱码必加
        case_sensitive=False,         # 字段名与环境变量名不区分大小写
    )


settings = Settings()
```

**核心特性：** 自动读取环境变量、支持 `.env` 文件、类型验证、默认值、安全性高。

安装（本仓库已安装，勿重复执行）：

```bash
uv add pydantic-settings
```

## 三、取值优先级（必须记住）

从高到低：

| 优先级 | 来源 | 典型场景 |
| --- | --- | --- |
| 1 | 实例化时传入的参数 `Settings(app_name="x")` | 单元测试里临时覆盖 |
| 2 | **操作系统环境变量** `os.environ` | Docker `-e`、K8S ConfigMap、CI 变量 |
| 3 | **`.env` 文件** | 本地开发，方便随手改 |
| 4 | 代码里的字段默认值 | 兜底，保证"零配置也能跑起来" |

**这条链解释了容器化部署的原理**：镜像里不带任何密码，启动容器时用环境变量注入（`docker run -e DATABASE_URL=...`），所以同一个镜像能在所有环境使用。

## 四、.env 文件规范

`.env` 就是最朴素的 `KEY=VALUE` 文本（课案写法全大写）：

```bash
APP_NAME="我的生产应用"
DATABASE_URL="mysql+pymysql://root:Sidnasa25@localhost:3306/my_database"
ADMIN_EMAIL="prod@example.com"
```

约定：

| 规则 | 说明 |
| --- | --- |
| 命名 | 全大写 + 下划线（`APP_NAME`），与字段 `app_name` 对应 |
| 引号 | 值里有空格/`#`/等号时加引号 |
| 注释 | `#` 开头 |
| 布尔 | `true/false`、`1/0`、`yes/no` 都能被正确解析 |
| **绝不入库** | `.env` 必须写进 `.gitignore`；提供 `.env.example` 作为模板 |
| 编码 | UTF-8（`env_file_encoding="utf-8"`） |

**`.env.example` 的作用**：告诉同事"这个项目需要哪些配置项"，但**不含真实值**。新人克隆项目后：

```bash
cp .env.example .env      # Linux/macOS
copy .env.example .env    # Windows
# 然后填写自己的密码
```

## 五、多环境配置

课案提到的做法：

- `.env.dev` 开发环境配置
- `.env.prod` 生产环境配置
- 可直接使用环境变量覆盖

两种实现方式：

**方式一：按环境切换 env_file（推荐）**

```python
import os
from pydantic_settings import BaseSettings, SettingsConfigDict

ENV = os.getenv("APP_ENV", "dev")   # 默认开发环境


class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file=f".env.{ENV}", env_file_encoding="utf-8")
```

```bash
APP_ENV=prod python main.py     # Linux/macOS
$env:APP_ENV="prod"; python main.py   # Windows PowerShell
```

**方式二：实例化时显式指定（本目录示例脚本用的方式，便于演示）**

```python
dev_settings = Settings(_env_file=".env.dev")
prod_settings = Settings(_env_file=".env.prod")
```

**生产环境的进一步做法：**
- 密钥类配置（数据库密码、JWT 密钥、第三方 API Key）交给**密钥管理平台**（阿里云 KMS、Vault、K8S Secret）下发，避免明文躺在服务器文件里；
- 生产环境只允许通过环境变量注入，`.env` 文件仅用于本地开发；
- 启动时打印一次"脱敏后的配置摘要"，方便排障且不泄露密钥。

## 六、进阶技巧

### 1. 敏感字段用 SecretStr

```python
from pydantic import SecretStr

class Settings(BaseSettings):
    jwt_secret: SecretStr = SecretStr("change-me")

settings = Settings()
print(settings.jwt_secret)                 # **********（自动打码）
print(settings.jwt_secret.get_secret_value())   # 真实值（只在真正签名时调用）
```

好处：不小心 `logger.info(settings)` 或把配置塞进报错响应里，密钥也不会泄露。

### 2. 字段校验与约束

```python
from pydantic import Field, field_validator

class Settings(BaseSettings):
    port: int = Field(default=8000, ge=1, le=65535)
    cors_origins: list[str] = Field(default_factory=list)   # 复杂类型用 default_factory

    @field_validator("port")
    @classmethod
    def not_default_db_port(cls, v: int) -> int:
        if v in (3306, 6379):
            raise ValueError("不要使用数据库默认端口")
        return v
```

**"配置写错 → 启动即失败"** 是这个库最大的价值：错误暴露在部署阶段，而不是半夜运行到某个接口时才炸。

### 3. 嵌套/分组配置

```python
class DatabaseSettings(BaseSettings):
    model_config = SettingsConfigDict(env_prefix="DB_")   # DB_HOST / DB_PORT
    host: str = "127.0.0.1"
    port: int = 3306
```

本仓库根目录的 `config.py` 用的就是这个思路：既有扁平字段（`settings.mysql_url`），也有分组字段（`settings.llm.api_key`、`settings.redis.host`）。

### 4. 缓存配置对象

```python
from functools import lru_cache
from config import Settings

@lru_cache
def get_settings() -> Settings:
    return Settings()      # 全局只解析一次，避免每个请求都读一遍 .env
```

在 FastAPI 中还可以把 `get_settings` 作为依赖注入：`def route(s: Settings = Depends(get_settings))`，测试时用 `app.dependency_overrides` 换成测试配置。
