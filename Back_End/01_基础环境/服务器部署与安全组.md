# 服务器部署与安全组（后端开发基础 · API 开发部署章节）

> 对应课案章节：`后端开发基础 → API 开发部署 → 服务器准备 / 远程连接 / 安装 Docker / 服务器安全组和防火墙`
> 目标：把本地写好的 FastAPI / Flask 服务，稳稳当当地部署到一台云服务器上，并让公网能访问。

---

## 一、整体流程先看一遍

```
① 租 ECS 服务器  →  ② SSH 远程连接  →  ③ 安装 Docker  →  ④ 上传/构建镜像
      ↓                                                        ↓
⑧ 验证访问  ←  ⑦ 检查程序端口 & 安全组 & 防火墙  ←  ⑥ 启动容器（-p 映射端口）
```

**最重要的一条经验：** 访问不了 `http://公网IP:8099` 时，一定按 **程序端口 → 安全组 → 防火墙** 的顺序排查，不要瞎改代码。

## 二、租用 ECS 服务器

1. 登录阿里云控制台 → **云服务器 ECS** → **实例与镜像 > 实例** → **创建实例**。
2. 选择 **自定义购买**：
   - **付费方式**：教学、临时测试选 **按量付费**（用完释放，按小时计费）；长期运行选 **包年包月**。
   - **地域**：选离自己近的（如华东1-杭州），延迟低。
   - **规格**：训练/教学场景 **4 核 8G** 足够，**不需要 GPU**（MySQL、Redis、FastAPI 都是 CPU 型负载）。
   - **镜像**：Ubuntu 22.04/24.04 LTS 或 Alibaba Cloud Linux；**勾选"提前安装 Docker"**（部分镜像有该选项）。
   - **系统盘**：40G 起步，日志/镜像很吃空间。
   - **带宽**：按量带宽 5~10 Mbps 即可；公网 IP 一定要分配。
   - **登录凭证**：设置 root 密码（或绑定密钥对）。
3. 创建完成后，在实例列表记下 **公网 IP**。
4. **成本提醒**：按量付费的机器不用时在控制台 **停机**（注意"节省停机模式"才不收计算费），长期不用直接 **释放实例**。

> 训练建议：只在需要演示时开机，讲完就停机，避免账单失控。

## 三、远程连接服务器（SSH）

服务器在云端机房，我们通过 **SSH（Secure Shell，22 端口，加密）** 连接到它的终端。

### 方式一：命令行 / PowerShell

```bash
ssh root@公网IP                 # 默认 22 端口
ssh -p 2222 root@公网IP         # 服务商改过端口时
scp -r ./book_api root@公网IP:/opt/app   # 上传项目目录
```

### 方式二：FinalShell（推荐给初学者）

下载：https://www.hostbuf.com/t/988.html

操作步骤：
1. 打开 FinalShell → 左上角 **文件夹图标** → **新建连接** → 选择 **SSH 连接**。
2. 填写：
   - **名称**：随意，如 `my-ecs`
   - **主机**：实例的**公网 IP**
   - **端口**：默认 `22`
   - **用户名**：`root`
   - **密码**：创建实例时设置的密码
3. 双击连接，看到类似下面的欢迎界面就成功了：

```
Welcome to Ubuntu 24.04 LTS (GNU/Linux 6.8.0 x86_64)
Last login: ...
root@my-ecs:~#
```

FinalShell 的三个好用的点：
- 左侧有 **SFTP 文件树**，可以直接拖拽上传/下载文件（比 `scp` 直观）；
- 底部有 **资源监控**（CPU/内存/网络曲线），能立刻看出服务是不是把机器跑满了；
- 支持 **多标签**，一个窗口同时连多台机器。

> 安全提醒：不要用弱密码；生产环境建议改用密钥登录并关闭密码登录。

## 四、安装 Docker

教学场景可以用第三方一键脚本快速装好：

```shell
# 一键安装 Docker + Compose + 配置国内镜像源（第三方脚本，生产请先看脚本内容）
bash <(wget -qO- https://xuanyuan.cloud/docker.sh)

# 手动补一个独立版 docker-compose（老命令）
sudo curl -L "https://github.com/docker/compose/releases/latest/download/docker-compose-$(uname -s)-$(uname -m)" -o /usr/local/bin/docker-compose
sudo chmod +x /usr/local/bin/docker-compose
docker-compose --version
```

安装完成后必须自检：

```shell
sudo systemctl status docker      # 期望：Active: active (running)
sudo docker run hello-world       # 期望：Hello from Docker!
sudo docker compose version       # 期望：Docker Compose version v2.x.x
```

## 五、安全组与防火墙：两道门都要开

这是整个部署章节**最关键的排障知识**。

### 5.1 为什么是两道门？

| 位置 | 名称 | 在哪配置 | 作用 |
| --- | --- | --- | --- |
| 第一道 | **安全组（Security Group）** | 云厂商控制台（阿里云/腾讯云） | 云端虚拟防火墙，决定**哪些流量能到达这台机器** |
| 第二道 | **防火墙（ufw / firewalld）** | Linux 系统内部 | 系统自己的端口规则 |

请求路径：
```
公网客户端 → 云安全组（放行了吗？）→ 系统防火墙（放行了吗？）→ 程序端口（在监听吗？）→ 应用
```
**任何一道没放行，都会表现为"连接超时"或"拒绝连接"。**

### 5.2 第一步：先确认程序真的在监听端口

在服务器上执行：

```bash
ss -tulnp | grep 8099          # 有没有进程监听 8099？
docker ps                      # 容器在跑吗？端口映射对吗？
curl http://127.0.0.1:8099/docs   # 服务器本机能不能访问？
```

如果本机 `curl` 都不通，问题在**程序**（没启动 / 启动报错 / 端口写错 / 只监听 127.0.0.1），与安全组无关。

> **易踩的坑：** 应用里写 `uvicorn.run(app, host="127.0.0.1")` 时**只监听回环地址**，容器外/公网永远访问不到。
> 部署到容器/服务器时必须写 `host="0.0.0.0"`。

### 5.3 第二步：在云控制台放行安全组

阿里云路径：**云服务器 ECS → 网络与安全 → 安全组 → 配置规则 → 入方向 → 手动添加**

| 字段 | 建议值 | 说明 |
| --- | --- | --- |
| 授权策略 | 允许 | 允许该流量进入 |
| 优先级 | 1 | 数字越小优先级越高 |
| 协议类型 | 自定义 TCP | 或选"全部 TCP" |
| 端口范围 | 8099/8099 | 单端口写 `8099/8099`；范围写 `8000/8100` |
| 授权对象 | 0.0.0.0/0 | 允许所有来源；生产建议只放行公司/家庭 IP |

也要确认 **出方向** 默认是允许全部（一般默认就是）。

安全组最佳实践：
- **最小开放**：只放行真正需要的端口（22、80、443、以及你的应用端口）。
- **不要把 3306 / 6379 / 19530 暴露到公网**，数据库和缓存只允许内网访问。
- 顺手把 22 端口限制为自己的 IP，能挡掉绝大多数爆破。

### 5.4 第三步：放行 Linux 防火墙

**Ubuntu（ufw）：**

```bash
sudo ufw status                          # 先看状态
sudo ufw allow 22/tcp                    # 先放行 SSH！（否则可能把自己关在门外）
sudo ufw allow 8099/tcp
sudo ufw allow 8000/tcp
sudo ufw reload
sudo ufw status numbered                 # 复核规则
```

**Alibaba Cloud Linux / CentOS / AlmaLinux（firewalld）：**

```bash
sudo firewall-cmd --state
sudo firewall-cmd --permanent --add-port=8099/tcp
sudo firewall-cmd --permanent --add-port=8000/tcp
sudo firewall-cmd --reload               # 不加这句，永久规则不生效
sudo firewall-cmd --list-ports           # 复核
```

> 有些云镜像（如 Alibaba Cloud Linux 默认）防火墙是关闭的，此时第二道门不存在，问题一定在安全组或程序本身。

### 5.5 第四步：分层测试

```bash
# 服务器本机
curl http://127.0.0.1:8099/docs

# 自己电脑（PowerShell / 浏览器）
curl http://公网IP:8099/docs
```

| 本机 | 公网 | 结论 |
| --- | --- | --- |
| ✅ | ✅ | 部署成功 |
| ✅ | ❌ | 安全组 或 防火墙 没放行（或应用只监听 127.0.0.1） |
| ❌ | ❌ | 程序没启动/报错，先看 `docker logs` |

## 六、端口约定与安全建议（本项目实践）

| 端口 | 用途 | 是否对公网开放 |
| --- | --- | --- |
| 22 | SSH 管理 | 是（建议限制来源 IP） |
| 80 / 443 | HTTP / HTTPS | 是 |
| 8099 | 本课案演示的 API 应用 | 是（教学用） |
| 3306 | MySQL | **否**，只走内网 |
| 6379 | Redis | **否**，只走内网 |
| 19530 | Milvus | **否**，只走内网 |

课案原文提到：MySQL 默认 3306、Redis 默认 6379，**生产上不要使用默认端口**，因为默认端口会被全网扫描器第一时间盯上；改端口 + 设置密码 + 只允许内网访问是最低要求。

## 七、把服务真正跑起来（完整命令串）

```bash
# ---------- 服务器上 ----------
mkdir -p /opt/app && cd /opt/app
# 用 FinalShell 拖拽或用 scp 把项目传上来，或直接从镜像仓库拉

# 方案 A：docker compose（推荐，含依赖服务）
docker compose up -d
docker compose ps
docker compose logs -f api

# 方案 B：单容器
docker build -t myapi:v1.0 .
docker run -d --name myapi --restart=unless-stopped -p 8099:80 myapi:v1.0

# ---------- 验证 ----------
curl http://127.0.0.1:8099/docs
# 浏览器打开 http://公网IP:8099/docs
```

**生产上还应该做：**
- 用 Nginx 反向代理 + HTTPS（证书可用 Let's Encrypt 免费申请），应用不直接暴露；
- 日志挂载到宿主机目录或接入日志收集，容器删了日志还在；
- 配置 `--restart=unless-stopped` 或 systemd 单元，保证服务器重启后服务自动拉起；
- 敏感配置（数据库密码、JWT 密钥）用环境变量/密钥管理下发，**不要写进镜像**。
